Ниже представлено развернутое и структурированное **Техническое задание (ТЗ)** для разработки прототипа / MVP первой версии (Core App) системы автоматизации первичной документации.

Фокус данного ТЗ — **создание каркаса (костяка) системы** с мультиарендной архитектурой, управлением организациями, логикой документов, имитацией работы с файлами и эквайрингом, а также изолированной панелью суперадминистратора.

---

# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)

**Наименование проекта:** Сервис учета и автоматизации первичной документации (Core Prototype)

**Технологический стек:** Next.js (App Router), TypeScript, Tailwind CSS, Shadcn UI, Supabase (PostgreSQL, Auth, RLS).

---

## 1. ОБЩИЕ ТРЕБОВАНИЯ И АРХИТЕКТУРА

### 1.1 Multi-Tenancy (Мультиарендность)

* **Изоляция данных:** База данных строится по принципу мультиарендности с жестким разделением по `company_id`.
* **Безопасность (RLS):** Все таблицы (`users`, `documents`, `counterparties`, `nomenclature`, `subscriptions`) имеют включенный **Row Level Security** в PostgreSQL. Пользователь видит и редактирует данные **только своей компании**.

### 1.2 Аутентификация и авторизация

* **Вход:** Авторизация по логину (Email) и паролю через Supabase Auth.
* **Профиль пользователя:**
* Возможность просмотра текущего профиля.
* Форма привязки/изменения **номера телефона** (с форматированием под КР: `+996 XXX XX-XX-XX`).
* Форма подтверждения / привязки дополнительной **электронной почты**.


* **Ролевая модель в рамках организации:**
1. `Owner / Admin` (Владелец): Полный доступ к компании, управление сотрудниками, подпиской и оплатой.
2. `Accountant` (Бухгалтер): Создание, редактирование, изменение статусов документов, просмотр справочников, экспорт данных.
3. `Manager` (Торговый представитель / Менеджер): Создание черновиков документов, просмотр только собственных созданных документов.

## 2. МОДУЛЬ «СУПЕР-АДМИНКА» (SUPER-ADMIN PANEL)

Изолированный раздел системы (доступный только пользователям с глобальным флагом `is_super_admin = true`).

### 2.1 Функционал Суперадмина:

1. **Реестр организаций:**
* Просмотр списка всех зарегистрированных компаний в системе.
* Просмотр количества активных пользователей и объема документов по каждой компании.
* Возможность вручную принудительно заблокировать / разблокировать компанию.


2. **Управление подписками организаций:**
* Просмотр текущего тарифного плана компании.
* Ручное продление подписки, изменение лимита памяти (ГБ) или количества сотрудников.
* Просмотр истории транзакций и имитаций оплат.



---

## 3. МОДУЛЬ «ОРГАНИЗАЦИЯ И ПОДПИСКИ»

### 3.1 Онбординг / Создание организации

* Форма первого входа: если у пользователя нет привязанной компании, ему предлагается:
* **Создать новую компанию** (Поля: Название организации, ИНН [14 цифр], Юридический адрес, Телефон).


* Автоматическое присвоение пользователю, создавшему компанию, роли `Owner`.

### 3.2 Управление подпиской и имитация оплаты через QR

* **Экран подписки:**
* Отображение текущего статуса подписки (Активна / Истекла / Демо-период).
* Карточки тарифов (например: *Базовый — 3 000 сом/мес*, *Стандарт — 7 000 сом/мес*).


* **Модальное окно оплаты через QR-код (Имитация):**
* Выбор периода (1, 3, 6, 12 месяцев).
* Генерация динамического UI с **QR-кодом** (симуляция оплаты через MBank / Оптима / Элсом).
* Таймер ожидания оплаты (30 секунд).
* Кнопка **«Имитировать успешную оплату»** (для тестирования).
* *Поведениe:* При нажатии кнопки статус подписки компании в базе данных меняется на `Active`, дата окончания продлевается, а в реестр транзакций записывается фейковый платеж.

## 4. МОДУЛЬ «СПРАВОЧНИКИ» (LOOKUPS)

Справочники используются для быстрого подтягивания данных в документы.

### 4.1 Справочник Контрагентов (`counterparties`)

* **Реестр контрагентов:** Таблица с поиском и фильтрацией.
* **Форма создания/редактирования:**
* Название контрагента (ОсОО / ИП).
* ИНН (14 цифр, с валидацией длины).
* Статус плательщика НДС (Да/Нет).
* Контактный телефон, Комментарий.



### 4.2 Справочник Номенклатуры / Товаров (`nomenclature`)

* **Реестр товаров и услуг:**
* Наименование (например, *«Вода Легенда 1.5л ПЭТ»*).
* Артикул / Код товара.
* Единица измерения (шт, кг, литр, услуга).
* Базовая цена продажи / закупа (сом).

## 5. МОДУЛЬ «ДОКУМЕНТЫ» (DOCUMENTS CORE)

Центральный модуль системы, позволяющий вести учет первичной документации.

### 5.1 Реестр документов (Главный экран)

* **Табличный вид:**
* Дата создания, Тип документа, Контрагент, Сумма (сом), Статус, Автор (кто создал).


* **Фильтры:** По типам документов, по статусам, по периоду дат, по контрагенту.
* **Статусная модель:**
1. `Draft` (Черновик)
2. `Review` (На проверке)
3. `Approved` (Одобрен / Проверен)
4. `Rejected` (Отклонен)
5. `Posted_1C` (Проведен в 1С)



### 5.2 Создание и редактирование документа

* **Типы документов:**
* Реализация (Продажа)
* Закуп (Поступление)
* Оплата (Чек / Перевод)
* Авансовый отчет


* **Поля формы документа:**
* Выбор контрагента из Справочника.
* Дата документа и Номер документа.
* Табличная часть (Товары/Услуги): Выбор из Справочника номенклатуры, количество, цена, итоговая сумма (авторасчет).
* Примечание / Комментарий.



### 5.3 Имитация загрузки файлов (Drag-and-Drop)

* **Интерфейс загрузки:** Область прикрепления скана / фото накладной.
* **Логика имитации (Dropzone):**
* При перетаскивании файла или выборе с устройства запускается **Progress Bar (0% -> 100%)** продолжительностью 1.5–2 секунды.
* Файл **не сохраняется в облачное хранилище** (Cloudflare R2 не вызывается).
* В локальном состоянии компонента или в БД сохраняется **имитационная запись файла**:
* `file_name`: Имя загруженного файла (например, `scan_nakladnaya_102.pdf`).
* `file_size`: Размер (например, `1.8 MB`).
* `file_status`: `uploaded_mock`.


* Отображение плашки прикрепленного файла с возможностью его "удаления" из формы.

## 6. МОДУЛЬ «ЭКСПОРТ И ВЫГРУЗКА» (1C / EXCEL EXPORT)

Позволяет формировать структурированные данные для бухгалтерии.

### 6.1 Функционал экспорта:

* **Кнопка «Выгрузить в Excel / 1С»:**
* Вызов модального окна с выбором периода и фильтра по статусу (например, выгружать только `Approved`).


* **Логика работы (Client-side):**
* Сбор массива выбранных документов прямо из состояния приложения / Supabase.
* Формирование `.xlsx` файла на стороне клиента (библиотека `SheetJS / xlsx`).
* Скачивание файла браузером с наименованием вида: `export_1c_[company_name]_[date].xlsx`.

## 7. СХЕМА БАЗЫ ДАННЫХ (КРАТКИЙ DRAFT ДЛЯ SUPABASE)

```sql
-- 1. Организации
CREATE TABLE companies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  inn VARCHAR(14) NOT NULL,
  address TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Пользователи
CREATE TABLE users (
  id UUID PRIMARY KEY REFERENCES auth.users(id),
  company_id UUID REFERENCES companies(id),
  full_name TEXT NOT NULL,
  phone VARCHAR(20),
  email TEXT NOT NULL,
  role TEXT CHECK (role IN ('owner', 'accountant', 'manager')) DEFAULT 'manager',
  is_super_admin BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. Подписки компаний
CREATE TABLE subscriptions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID REFERENCES companies(id) UNIQUE,
  plan_type TEXT DEFAULT 'basic',
  status TEXT CHECK (status IN ('active', 'expired', 'trial')) DEFAULT 'trial',
  expires_at TIMESTAMP WITH TIME ZONE DEFAULT (NOW() + INTERVAL '14 days'),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. Справочник Контрагентов
CREATE TABLE counterparties (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID REFERENCES companies(id) NOT NULL,
  name TEXT NOT NULL,
  inn VARCHAR(14),
  phone VARCHAR(20),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 5. Справочник Номенклатуры
CREATE TABLE nomenclature (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID REFERENCES companies(id) NOT NULL,
  title TEXT NOT NULL,
  code TEXT,
  unit TEXT DEFAULT 'шт',
  price NUMERIC(12, 2) DEFAULT 0.00,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 6. Документы
CREATE TABLE documents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID REFERENCES companies(id) NOT NULL,
  author_id UUID REFERENCES users(id) NOT NULL,
  counterparty_id UUID REFERENCES counterparties(id),
  doc_type TEXT CHECK (doc_type IN ('realization', 'purchase', 'payment', 'advance')) NOT NULL,
  status TEXT CHECK (status IN ('draft', 'review', 'approved', 'rejected', 'posted_1c')) DEFAULT 'draft',
  total_amount NUMERIC(12, 2) DEFAULT 0.00,
  comment TEXT,
  mock_file_name TEXT,
  mock_file_size TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

```
