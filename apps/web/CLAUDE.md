# apps/web — интерфейс Next.js

- App Router, React, TypeScript, Tailwind CSS v4. Сборка `output: "standalone"` — тот же сайт на Vercel и в Docker.
- API — только пакет `@buhuchet/api`, подключён одним файлом `app/api/[[...route]]/route.ts` (runtime `nodejs`). Своих серверных обработчиков данных здесь нет.
- Запрещено: Server Actions для данных (`"use server"`), Edge Runtime (`export const runtime = 'edge'`), прямые запросы к базе из компонентов, `@vercel/*` и `@supabase/*` (проверяет `pnpm check:portability`).
- Страницы за входом работают как одностраничное приложение: данные берут из API типизированным клиентом Hono (`src/api-client.ts`) через TanStack Query (`QueryProvider` в оболочке, `src/query.tsx`); формы — React Hook Form со схемами Zod из `@buhuchet/shared`.
- Сохранение записи с версией: ответ 409 (`isRecordChanged` из `@buhuchet/shared`) — правка не сохранена; над формой `RecordChangedNotice` из `@buhuchet/ui`, «Перечитать» заново загружает запись (новая версия и значения), пользователь правит снова. Молча повторять запрос с новой версией нельзя.
- Тексты интерфейса — только из словаря (модуль «Локализация»): новый текст — ключ с русским текстом в словаре своего модуля `packages/domain/src/l10n/<модуль>-texts.ts` (в `UI_TEXTS`, `l10n/texts.ts`, — одна строка модуля), на экране — `const t = useT(); t('ключ', { имя: значение })` (`src/l10n/provider.tsx`), в серверном компоненте — `await getT()` (`src/l10n/server.ts`). Ключ, который уже есть в разделе `localization` refDB.json (`nav.*`, `btn.*`, `grid.*`, `err.*`…), берётся с тем же текстом, а не заводится заново: иначе правка в «Локализации» не дойдёт до экрана. Строки с русскими буквами в коде сайта запрещает ESLint (комментарии и названия тестов можно).
- Словарь приходит в первом ответе страницы: корневой макет (`app/layout.tsx`) читает его на сервере методом `/api/l10n` через API в том же процессе — к базе страница не обращается. Ошибку ответа API экран показывает через `useErrorText()`: текст словаря по коду (`err.<код>`, при `details.variant` — сначала `err.<код>.<вариант>`) с подстановками из `details` ответа, текст ответа — только если ключа нет или не хватает подстановки. Новый код ошибки, который увидит пользователь, — ключ `err.<код>` с тем же текстом, что у сервера.
- Как в прототипе: граница ПК и телефона 768 px, на телефоне нижняя панель ровно из 4 модулей и «≡ Другие модули», у каждой карточки «На весь экран». Сверяться с `spec/prototype/src/js/ui` и `spec/prototype/src/css`.
- Страницы за входом — `/app/<модуль>/<вкладка>`: макет `app/app/layout.tsx` (вошёл, сменил временный пароль, есть модули — иначе `/login`) рисует оболочку (`src/shell/shell.tsx`): левая панель модулей, верхняя панель, ряд вкладок и «+ Добавить»; на телефоне — нижняя панель, панель «Меню» и листание вкладок свайпом. Экран модуля регистрируется в реестре `src/screens/module-screen.tsx` (`ModuleScreen` по модулю и вкладке), а не своей папкой маршрута: тот же экран рисует и общий маршрут `app/app/[module]/[[...tab]]`, и соседняя вкладка, которая въезжает при свайпе. Заголовок, вкладки, кнопку добавления и поле поиска экран не рисует — выбранный способ «+ Добавить» и строку поиска берёт хуком `useShell()` (`src/shell/context.ts`). Модули меню — с сервера (`/api/auth/me` → `modules`), вкладки и способы добавления по правам — реестр `src/shell/modules.ts`, четыре модуля нижней панели — `BOTTOM_NAV` там же (docs/decisions.md, п. 25 и 26).
- Формы — React Hook Form с `zodResolver` и схемой из `@buhuchet/shared`; сообщения схемы — ключи словаря, на экран их выводит `fieldError(t, errors.поле)` (`src/auth/fields.tsx`, числа правил — `fieldErrorText`). Поля — `Field`, `FormGrid`, `inputClass()` из `@buhuchet/ui`; `register` вызывать до разметки в порядке полей на экране, иначе фокус ошибки встанет не на первое поле. Запрос — `callApi(() => api.api…)` (`src/api-client.ts`): при ошибке ответа — `setError(поле, { type: 'server', message: errorText(res.error) })` (docs/decisions.md, п. 28).
- В именах id и классов нет слов `ad`, `ads`, `adv`, `banner`, `sponsor` (между «-» и «_»): блокировщики рекламы прячут такие элементы на любом сайте (общие правила EasyList вида `###ad-…`); так пропадало поле кода при входе в Админку (`ad-code`). Проверяет `src/ad-block-names.test.ts`.
- Окна, подтверждения и уведомления — `Modal`, `ConfirmDialog`, `useToast()` из `@buhuchet/ui` (тексты и выбор «На весь экран» им даёт оболочка, cookie `bh_max`); свой оверлей не рисовать. Форма в окне передаёт `kind="form"` и `dirty` (React Hook Form `formState.isDirty`), карточка с полями ввода (как «Мой профиль») — тоже `dirty` — тогда протяжка вниз и «Назад» спрашивают «Закрыть без сохранения?»; выход при несохранённых изменениях в открытой форме спрашивает «Выйти без сохранения?» (docs/deviations.md, п. 27). Пустой список — `EmptyState`, при поиске или фильтре — `NothingFound` (docs/decisions.md, п. 27).
- Шкала статусов и «История статусов» на экране — через `src/status/status-view.ts`: `scaleView`, `miniView`, `historyView` превращают статус записи, её историю (`statusEvents` из ответа API) и то, что разрешил модуль (следующие шаги, шаг для отката с правом «Откат статусов», закрытые шаги с причиной), в пропсы компонентов `@buhuchet/ui` с текстами словаря. Отдельная страница вне оболочки получает окна и уведомления из `UiProviders` (`src/shell/ui-providers.tsx`). Образцы компонентов на демо-записях — `/samples` (`src/samples/`), на рабочем сайте её нет.
- Окно и выдвижная панель регистрируются хуком `useBackClose` из `@buhuchet/ui`: кнопка «Назад» телефона закрывает их, не уходя со страницы; переход из открытого окна — с заменой записи истории (`replace`), иначе «Назад» вернёт к закрытому окну. Всплывающее окошко (`Popover`) «Назад» просто закрывает, переход при этом идёт (как `closePop` прототипа).
- Цвета — только классы темы (`bg-pane`, `text-ink`, `text-muted`, `border-line`, `bg-accent`…, `packages/ui/src/theme.css`), без `slate-*` и `dark:`: тёмную тему дают переменные. Выбор на устройстве (тема, левая панель, раскрытые ветки, развёрнутые окна) — cookie `bh_theme`, `bh_nav`, `bh_tree`, `bh_max` (`src/shell/prefs.ts`), не localStorage.
- Экраны раскладываются по модулям ТЗ; общие компоненты — в `packages/ui`.
- `vercel.json` — вызов `/api/cron/tick` раз в минуту (сверяется с `PLATFORM_CRON_ENTRIES` тестом); региона в нём нет — он в настройках каждого проекта Vercel (стенд — dub1, рабочий сайт — fra1, docs/deploy.md).
- Списки — `DataGrid` из `@buhuchet/ui` (docs/decisions.md, п. 29): настройки вида — `useViewSettings('<ключ списка>')` (`src/lists/view-settings.ts`: все настройки пользователя одним запросом, правка сразу на экране и через 300 мс на сервере), страница с сервера — `useListPage` (`src/lists/use-list-page.ts`: сортировка, размер, группировка и итоги из настроек, номер страницы и фильтры на экране, поиск из `useShell()` через 300 мс, при смене поиска, фильтра или группировки — первая страница, прежняя страница видна, пока грузится новая; возвращает `params` и `visible` для выгрузки), «В Excel» — `useListExport` (`src/lists/export.ts`, только при праве `access.can('export')`), «Статистика» модуля — `useModuleStats` (`src/lists/stats.ts`) и вкладка в `SCREENS_WITH_PLATES` (`src/screens/module-screen.tsx`), тексты — `useGridLabels('<ключ>.count')` (`src/lists/grid-labels.ts`). (docs/decisions.md, п. 30.) Ключ нового списка — в `GRID_KEYS` (`@buhuchet/domain`), иначе сервер не сохранит его вид. Пример — «Сотрудники» → список (`src/staff/staff-list.tsx`), его действия над записью — `useStaffActions` (`src/staff/staff-actions.tsx`: пункты меню и окна подтверждения; docs/decisions.md, п. 31).

О-69): экран передаёт одно и то же описание доски (`BoardChoice`: `by`, `def`) в `useListPage({ kanban })` и в `DataGrid kanban` — на доске `useListPage` сам запрашивает группировку по полю столбцов и суммы видимых числовых столбцов. - Окно, которое открывают из списка или меню, хранит состояние «слотом» (`src/dialog-slot.ts`: `openSlot(data)`, `closeSlot`): окно закрывается с анимацией, а новый номер `n` даёт новое окно.
