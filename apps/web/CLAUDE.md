# apps/web — интерфейс Next.js

- App Router, React, TypeScript, Tailwind CSS v4. Сборка `output: "standalone"` — тот же сайт на Vercel и в Docker.
- API — только пакет `@buhuchet/api`, подключён одним файлом `app/api/[[...route]]/route.ts` (runtime `nodejs`). Своих серверных обработчиков данных здесь нет.
- Запрещено: Server Actions для данных (`"use server"`), Edge Runtime (`export const runtime = 'edge'`), прямые запросы к базе из компонентов, `@vercel/*` и `@supabase/*` (проверяет `pnpm check:portability`).
- Страницы за входом работают как одностраничное приложение: данные берут из API типизированным клиентом Hono (`src/api-client.ts`) через TanStack Query (`QueryProvider` в оболочке, `src/query.tsx`); формы — React Hook Form со схемами Zod из `@buhuchet/shared`.
- Сохранение записи с версией: ответ 409 (`isRecordChanged` из `@buhuchet/shared`) — правка не сохранена; над формой `RecordChangedNotice` из `@buhuchet/ui`, «Перечитать» заново загружает запись (новая версия и значения), пользователь правит снова. Молча повторять запрос с новой версией нельзя.
- Тексты интерфейса — только из словаря (модуль «Локализация»): новый текст — ключ с русским текстом в словаре своего модуля `packages/domain/src/l10n/<модуль>-texts.ts` (в `UI_TEXTS`, `l10n/texts.ts`, — одна строка модуля), на экране — `const t = useT(); t('ключ', { имя: значение })` (`src/l10n/provider.tsx`), в серверном компоненте — `await getT()` (`src/l10n/server.ts`). Ключ, который уже есть в разделе `localization` refDB.json (`nav.*`, `btn.*`, `grid.*`, `err.*`…), берётся с тем же текстом, а не заводится заново: иначе правка в «Локализации» не дойдёт до экрана. Строки с русскими буквами в коде сайта запрещает ESLint (комментарии и названия тестов можно).
- Словарь приходит в первом ответе страницы: корневой макет (`app/layout.tsx`) читает его на сервере методом `/api/l10n` через API в том же процессе — к базе страница не обращается. Ошибку ответа API экран показывает через `useErrorText()`: текст словаря по коду (`err.<код>`, при `details.variant` — сначала `err.<код>.<вариант>`) с подстановками из `details` ответа, текст ответа — только если ключа нет или не хватает подстановки. Новый код ошибки, который увидит пользователь, — ключ `err.<код>` с тем же текстом, что у сервера.
- Как в прототипе: граница ПК и телефона 768 px, на телефоне нижняя панель ровно из 4 модулей и «≡ Другие модули», у каждой карточки «На весь экран». Сверяться с `spec/prototype/src/js/ui` и `spec/prototype/src/css`.
- Страницы за входом — `/app/<модуль>/<вкладка>`: макет `app/app/layout.tsx` (вошёл, сменил временный пароль, есть модули — иначе `/login`) рисует оболочку (`src/shell/shell.tsx`): левая панель модулей, верхняя панель, ряд вкладок и «+ Добавить»; на телефоне — нижняя панель, панель «Меню» и листание вкладок свайпом. Экран модуля регистрируется в реестре `src/screens/module-screen.tsx` (`ModuleScreen` по модулю и вкладке), а не своей папкой маршрута: тот же экран рисует и общий маршрут `app/app/[module]/[[...tab]]`, и соседняя вкладка, которая въезжает при свайпе. Заголовок, вкладки, кнопку добавления и поле поиска экран не рисует — выбранный способ «+ Добавить» и строку поиска берёт хуком `useShell()` (`src/shell/context.ts`). Модули меню — с сервера (`/api/auth/me` → `modules`), вкладки и способы добавления по правам — реестр `src/shell/modules.ts`, четыре модуля нижней панели — `BOTTOM_NAV` там же (docs/decisions.md, п. 25 и 26).
- Формы — React Hook Form с `zodResolver` и схемой из `@buhuchet/shared`; сообщения схемы — ключи словаря, на экран их выводит `fieldError(t, errors.поле)` (`src/auth/fields.tsx`, числа правил — `fieldErrorText`). Поля — `Field`, `FormGrid`, `inputClass()` из `@buhuchet/ui`; `register` вызывать до разметки в порядке полей на экране, иначе фокус ошибки встанет не на первое поле. Запрос — `callApi(() => api.api…)` (`src/api-client.ts`): при ошибке ответа — `setError(поле, { type: 'server', message: errorText(res.error) })` (docs/decisions.md, п. 28).
- Окна, подтверждения и уведомления — `Modal`, `ConfirmDialog`, `useToast()` из `@buhuchet/ui` (тексты и выбор «На весь экран» им даёт оболочка, cookie `bh_max`); свой оверлей не рисовать. Форма в окне передаёт `kind="form"` и `dirty` (React Hook Form `formState.isDirty`), карточка с полями ввода (как «Мой профиль») — тоже `dirty` — тогда протяжка вниз и «Назад» спрашивают «Закрыть без сохранения?»; выход при несохранённых изменениях в открытой форме спрашивает «Выйти без сохранения?» (docs/deviations.md, п. 27). Пустой список — `EmptyState`, при поиске или фильтре — `NothingFound` (docs/decisions.md, п. 27).
- Шкала статусов и «История статусов» на экране — через `src/status/status-view.ts`: `scaleView`, `miniView`, `historyView` превращают статус записи, её историю (`statusEvents` из ответа API) и то, что разрешил модуль (следующие шаги, шаг для отката с правом «Откат статусов», закрытые шаги с причиной), в пропсы компонентов `@buhuchet/ui` с текстами словаря. Отдельная страница вне оболочки получает окна и уведомления из `UiProviders` (`src/shell/ui-providers.tsx`). Образцы компонентов на демо-записях — `/samples` (`src/samples/`), на рабочем сайте её нет.
- Окно и выдвижная панель регистрируются хуком `useBackClose` из `@buhuchet/ui`: кнопка «Назад» телефона закрывает их, не уходя со страницы; переход из открытого окна — с заменой записи истории (`replace`), иначе «Назад» вернёт к закрытому окну. Всплывающее окошко (`Popover`) «Назад» просто закрывает, переход при этом идёт (как `closePop` прототипа).
- Цвета — только классы темы (`bg-pane`, `text-ink`, `text-muted`, `border-line`, `bg-accent`…, `packages/ui/src/theme.css`), без `slate-*` и `dark:`: тёмную тему дают переменные. Выбор на устройстве (тема, левая панель, раскрытые ветки, развёрнутые окна) — cookie `bh_theme`, `bh_nav`, `bh_tree`, `bh_max` (`src/shell/prefs.ts`), не localStorage.
- Экраны раскладываются по модулям ТЗ; общие компоненты — в `packages/ui`.
- `vercel.json` — регион dub1 (как у базы стенда, docs/deviations.md п. 1) и вызов `/api/cron/tick` раз в минуту; сверяется с `PLATFORM_CRON_ENTRIES` тестом.
- Списки — `DataGrid` из `@buhuchet/ui` (docs/decisions.md, п. 29): настройки вида — `useViewSettings('<ключ списка>')` (`src/lists/view-settings.ts`: все настройки пользователя одним запросом, правка сразу на экране и через 300 мс на сервере), страница с сервера — `useListPage` (`src/lists/use-list-page.ts`: сортировка, размер, группировка и итоги из настроек, номер страницы и фильтры на экране, поиск из `useShell()` через 300 мс, при смене поиска, фильтра или группировки — первая страница, прежняя страница видна, пока грузится новая; возвращает `params` и `visible` для выгрузки), «В Excel» — `useListExport` (`src/lists/export.ts`, только при праве `access.can('export')`), «Статистика» модуля — `useModuleStats` (`src/lists/stats.ts`) и вкладка в `SCREENS_WITH_PLATES` (`src/screens/module-screen.tsx`), тексты — `useGridLabels('<ключ>.count')` (`src/lists/grid-labels.ts`). (docs/decisions.md, п. 30.) Ключ нового списка — в `GRID_KEYS` (`@buhuchet/domain`), иначе сервер не сохранит его вид. Пример — «Сотрудники» → список (`src/staff/staff-list.tsx`), его действия над записью — `useStaffActions` (`src/staff/staff-actions.tsx`: пункты меню и окна подтверждения; docs/decisions.md, п. 31).
- Окно, которое открывают из списка или меню, хранит состояние «слотом» (`src/dialog-slot.ts`: `openSlot(data)`, `closeSlot`): окно закрывается с анимацией, а новый номер `n` даёт новое окно. Ключ окна — с приставкой (`card-${n}`, `form-${n}`), чтобы не совпасть с соседними окнами. Окно с полями ввода открывается, когда его данные загружены (`client.fetchQuery(...)` до `openSlot`), — фокус сразу в первом поле. Пример — «Сотрудники» и «Роли» (`src/staff/staff-actions.tsx`, `src/roles/roles-list.tsx`; docs/decisions.md, п. 34).
- «Моя организация» (`src/org/`, docs/decisions.md, п. 35): данные — `org-data.ts` (`orgProfileQuery`, `policyQuery`, `policyHistoryQuery`, `roleOptionsQuery`), после сохранения — `useOrgRefresh()`: перечитать данные модуля, а при смене функций и названия — и оболочку (`router.refresh()`: модули меню и название организации приходят с сервера). Учётная политика сохраняется каждым переключением, «Основное» и «Настройки» — кнопкой и только изменёнными полями. Окно профиля организации (`OrgProfileWindow`) открывает организация в левой панели и в панели «Меню» телефона. Сквозные тесты, которые меняют общую запись демо-организации, — в `e2e/*.shared.spec.ts` (идут после остальных и по одному).
- «Справочники» (`src/dicts/`, docs/decisions.md, п. 40): данные — `dicts-data.ts` (`catalogQuery` — каталог видов отчётов с органами, режимами, основаниями и льготами, читается за сеанс страницы один раз; `taxesQuery` — «Налоги и ставки» с названиями ГКЭД; `typeSettingsQuery` — настройки организации по видам), после сохранения — `useDictsRefresh()`. Вкладка «Виды отчётов» — `ReportTypesList` (переключатели в строке сохраняются сразу), форма вида — `TypeView`, описание вида и налогов — `TypeGuide`, `TypeDesc`, `TaxGuide` (`type-guide.tsx`, прототип `pkDescHtml`, `taxGuideHtml`). «Выбор налогов» — `useTaxPick()` → `{ open, dialog }`: окно ставится в разметку экрана, `open()` открывает его (его же откроет последний экран приветствия). Вкладка «Справочники платформы» — `PlatformDicts` (`platform-tab.tsx`, docs/decisions.md, п. 41): плитки (`platformTilesQuery`), окно справочника `PlatformDictWindow` со своим полем поиска и описаниями значений (`value-guide.tsx`; справочники для описаний — `valueDictsQuery`), «Поиск по всем значениям» по общему поиску. «Попросить добавить» и «Мои запросы» — `useDictRequest()`, `useMyRequests()` (`dict-request.tsx`); способ «+ Добавить» модуля разбирает `useDictsAddRequest({ catalog, request })` на обеих вкладках.
- «Деньги» (`src/money/`, docs/decisions.md, п. В-1): данные — `money-data.ts` (`banksQuery`, `orgAccountsQuery`, `myWalletsQuery`, `employeeWalletsQuery`; правка отвечает всем списком — он кладётся в кэш). Поля реквизита — `RequisiteFields` и проверка `checkDraft` (`requisite-form.tsx`, правила домена). Блоки ставятся в чужие экраны: `OrgAccountsBox` — «Основное» «Моей организации» и окно профиля организации, `MyWalletsBox` — «Мой профиль», `EmployeeWalletsBox` — карточка сотрудника.
- «Показатели контрагентов» (`src/kpi/`, docs/decisions.md, п. В-2): экран — `KpiScreen` (`kpi-screen.tsx`, вкладки «Ввод за месяц», «За период», «Не заполнено», «Настройка показателей»); данные — `kpi-data.ts` (`useKpiRefresh` после правки обновляет все экраны и счётчики); выбор месяца, периода и вида — `useKpiChoice` (`kpi-state.ts`). Ячейки ввода с переходом стрелками и вставкой блока из Excel — `kpi-table.tsx`. Счётчик «Не заполнено» модуля и точка «Меню» — `shell/tab-counts.ts` (`kpiMissingCount`, `menuDot`). Вкладка карточки `KpiCardTab` и значок списка `KpiMissingBadge` (`kpi-card-tab.tsx`) подключат карточка (2.11) и список контрагентов (2.10). «Ввод из Excel» (docs/decisions.md, п. В-3) — `useKpiImport()` (`kpi-import.tsx`): окно из двух шагов и «История загрузок»; файл не читается в браузере — он уходит на сервер телом запроса (`application/octet-stream`) на предпросмотр, «Применить» и файл ошибок; скачивание — `saveFile` (`lists/export.ts`).
- Блок «Файлы» карточки записи — `RecordFiles` (`src/files/`, docs/decisions.md, п. Г-1) с `source` записи: список (`filesQuery`), «Прикрепить» (проверка до загрузки `pickedFilesProblem`, загрузка `uploadFile`: начать → `PUT` в хранилище → закончить), «Скачать» по ссылке, «Удалить» с подтверждением. Внешний вид — `FilesBox` из `@buhuchet/ui`. Пока записей нет, блок стоит на странице образцов `/samples` (общие файлы организации).
- Файловый менеджер — `FilesManager` (`src/files/files-manager.tsx`, docs/decisions.md, п. Г-6): плашки по видам источника, общий список (`fileColumns`), окно файла с просмотром (`FileWindow`), «Загрузить файл» (`UploadDialog`), «Перейти к источнику» — `sourceOf`. «Хранилище файлов» — `FilesStorageBox` на вкладке «Моя организация» → «Настройки».
- «База знаний» (`src/kb/`, docs/decisions.md, п. Г-2): засчитывает шаги сервер, экран — только отклик. `useKbRuntime` (`kb-provider.tsx`) живёт в оболочке и кладёт в `KbContext` управление (`useKb()`: `go` — «Перейти» у шага, `hit` — первое использование, `openArticle`, `help` — «?» в шапке, `openLesson`) и окна поверх экрана (полоса урока, таймер «Посмотреть», «Шаг выполнен», статья, «Новый уровень»). Сохранение любой записи само сверяет шаги: `api-client.ts` после успешного изменяющего запроса шлёт событие `SAVED_EVENT`, кроме путей `NOT_SAVES`. Модуль, слитый позже, добавляет «Перейти» своих шагов в `KB_GO` (`kb-go.ts`: модуль, вкладка, что подсветить, `open` — способ «+ Добавить»); место для подсветки и первого использования — атрибуты `data-…` (`data-grid-columns-button`, `data-search-open`). «Пройти урок» функции — `useFeatureLesson(feature)`. Данные — `kb-data.ts` (`kbStateQuery` и вызовы отметок). «Показать как» и «Обзор экрана» (`src/kb/tour/`, п. Г-5): `useTour` в `useKbRuntime` (`useKb().show(шаг)`, `showScreen(экран)`, `resetKnown()`); что подсвечивать — `KB_SHOW_TARGETS` (`kb-show-targets.ts`): экран, слитый позже, добавляет строки своих элементов и при нужде атрибут `data-…`.
- «Новости» (`src/news/`, docs/decisions.md, п. Г-3): лента (`news-tab.tsx`), окно новости и «Что нового» (`news-provider.tsx`: `useNewsRuntime` в оболочке, `useNews().open`), markdown — `NewsMarkdown` (`news-md.tsx`, блоки из домена, без HTML), Админка — `news-admin.tsx` и редактор `news-editor.tsx`. «Что нового» спрашивается только после входа: `markSignedIn()` на странице входа, `takeSignedIn()` в оболочке (`signed-in.ts`). Счётчик непрочитанных — `newsUnreadQuery`; после отметок — `refreshNews`.
- «Приветствие» (`src/onboarding/`, docs/decisions.md, п. Г-4): окно из 6 экранов (`welcome-window.tsx`), `useWelcomeRuntime` в оболочке (`welcome-provider.tsx`): после входа `atLogin` спрашивает `GET /api/onboarding` раньше «Что нового» (открылось приветствие — «Что нового» в этот вход нет), `useWelcome().open('again' | 'retake')` — из «Мой уровень» и учётной политики. «Выбор налогов» — `TaxPickList` из `src/dicts/tax-pick.tsx`, окно «Включено функций» — `FeatureOnDialog` (`src/org/feature-on-dialog.tsx`, общее с переключателем политики).
- Админка (`src/admin/`): «Организации» — `orgs-list.tsx`, «Учётные записи» — `accounts-list.tsx` (меню записи — `accounts-menu.ts`, своя строка — по `userId` из `useShell()`). «Локализация» — `l10n-list.tsx` (плашки языков, словарь), окно «Текст интерфейса» — `ui-text-dialog.tsx` (после сохранения — `router.refresh()`: словарь страницы перечитывается). Видит только администратор платформы; модуль открывает `src/screens/module-screen.tsx`.
