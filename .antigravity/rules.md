# .antigravity/rules.md — Единый Системный Промпт и Правила Разработки Buhuchet.kg

Этот документ является Единым Источником Правды (SSOT) для AI-агентов (Antigravity). Все сгенерированные файлы, UI-компоненты, Server Actions, схемы PostgreSQL и структуры данных ОБЯЗАНЫ строго соответствовать изложенным ниже правилам.

---

## 1. БИЗНЕС-КОНТЕКСТ И СПЕЦИФИКА РЫНКА КЫРГЫЗСТАНА

### 1.1 Назначение платформы (Buhuchet.kg)
Buhuchet.kg — это облачная fullstack B2B-платформа и Telegram-экосистема электронного документооборота (ЭДО) и автоматизации первичного учета для торговых, дистрибьюторских и аутсорсинговых компаний Кыргызской Республики.

### 1.2 Региональная специфика КР:
1. **Идентификация контрагентов (ИНН КР):** ИНН юридических лиц и ИП в Кыргызстане состоит строго из **14 цифр** (например, `20101202310050`). Формы и Zod-схемы валидируют строго 14 цифр.
2. **Плательщики НДС:** Учет признака НДС (12%) для организаций и автоматическая подстановка в документы.
3. **Валюта учета:** Все расчеты выполняются в сомах (**KGS / сом**). Разделитель копеек — точка (`1500.50 сом`).
4. **Уставные документы:** Сканы уставов и свидетельств хранятся в Cloudflare R2 с разграничением прав доступа.

## 2. ОСНОВНОЙ СТЕК ТЕХНОЛОГИЙ

- **Fullstack Framework:** Next.js 14+ (App Router, React Server Components, Server Actions).
- **Язык программирования:** TypeScript (строгий режим `strict: true`).
- **Стилизация и UI:** Tailwind CSS, Shadcn UI, Lucide Icons.
- **База данных и Аутентификация:** Supabase (PostgreSQL, Row Level Security - RLS, Supabase Auth).
- **Хранилище сканов и файлов:** Cloudflare R2 (подключение через `@aws-sdk/client-s3`).
- **Фоновые задачи:** Upstash QStash / Telegram Webhooks (Next.js API Routes).
- **Экспорт данных:** SheetJS (`xlsx`) на стороне клиента.

---

## 3. СТАЦИОНАРНАЯ И РОЛЕВАЯ МОДЕЛЬ (RBAC)

### 3.1 Пользовательские Роли
1. `Manager` (Менеджер / Торговый представитель): Создание черновиков первички (`draft`), прикрепление сканов R2, просмотр своих документов.
2. `Accountant` (Бухгалтер): Просмотр первички в Split-screen режиме, прием/отклонение документов, массовый экспорт в 1С.
3. `Owner` (Владелец / Руководитель): Полный контроль компании, управление сотрудниками, зачисление кандидатов, партнерства B2B, эксклюзивный доступ к закрытию отчетных периодов.
4. `SuperAdmin` (Суперадминистратор): Глобальный контроль платформы, 1-кликовое одобрение организаций, Инспектор БД с прямым редактированием и удалением строк PostgreSQL.

### 3.2 Статусы B2B Документа и Партнерств
- **Документ:** `draft` ➔ `sent` ➔ `accepted` ➔ `processed` / `cancelled` / `recalled`.
- **Партнерство:** `pending` ➔ `approved` / `accepted` (автоматически создает взаимных контрагентов в обоих кабинетах).
- **Компания:** `pending_approval` ➔ `active` (после проверки суперадмином).

## 4. СТРОГИЕ ПРАВИЛА НАПИСАНИЯ КОДА (CODE STYLE & STANDARDS)

### 4.1 Строгий TypeScript и Zod Валидация
- Запрещено использовать тип `any`. Для всех сущностей, ответов API и пропсов должны быть определены явные `interface` или `type`.
- Все Server Actions мутации обязаны оборачиваться в **`createSafeAction`** (`lib/auth/safe-action.ts`) с проверкой Zod-схем.

### 4.2 Сжатие изображений на стороне клиента (Client-Side Compression)
- Все изображения и фото накладных ДО отправки в Cloudflare R2 ДОЛЖНЫ быть сжаты в браузере с помощью библиотеки `browser-image-compression` (макс. ширина — `1000px`, качество — `0.7`, размер — до 200 КБ).

### 4.3 Безопасность и Секреты
- Секретные ключи (`SUPABASE_SERVICE_ROLE_KEY`, `R2_SECRET_ACCESS_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`) используются строго на сервере.
- Клиентские компоненты (`"use client"`) имеют доступ только к публичным переменным `NEXT_PUBLIC_`.

### 4.4 Безопасность БД и Аппаратные Триггеры
- Каждая таблица БД обязана содержать поле `company_id` и подлежать RLS-изоляции.
- Таблицы `documents` и `files` защищены на уровне триггерной функции PostgreSQL `check_closed_period_lock()`, предотвращающей модификацию данных за закрытые отчетные периоды non-owner пользователями.

## 5. ОБЯЗАТЕЛЬНЫЙ ПРОЦЕСС ЗАВЕРШЕНИЯ ЗАДАЧ (DEFINITION OF DONE)

При завершении задачи AI-агент ОБЯЗАН:
1. Проверить компиляцию типов TypeScript: `npx tsc --noEmit`.
2. Проверить производственную сборку Next.js: `npm run build`.
3. Обновить `docs/ARCHITECTURE.md` и `docs/DATABASE.md` при добавлении новых модулей или таблиц.
4. Сохранить план разработки и walkthrough отчет в `.ai_artifacts/plans/` и `.ai_artifacts/walkthroughs/`.
