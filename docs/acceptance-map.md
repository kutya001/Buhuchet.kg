# Карта приёмки: пункт ТЗ → сквозной тест

Каждый пункт раздела ТЗ «Как проверить, что всё работает» — отдельный сквозной тест Playwright на ПК (1280 px) и телефоне (390 px). `pnpm check:acceptance` (в каждой проверке PR) падает, если у пункта нет теста, файла или названия теста.

Формат строки: `- <пункт ТЗ> → e2e/<файл>.spec.ts › <название теста>`. Пункт, для которого тест ещё не написан: `- <пункт> → нет теста` (проверка упадёт, поэтому так пишут только в ветке, пока задача не готова).

## Этап 0. Фундамент

- Страница «здоровья» открывается на ПК и телефоне и показывает, что база и хранилище доступны → e2e/health.spec.ts › страница «здоровья» показывает, что база и хранилище доступны
- API здоровья отвечает и не кэшируется → e2e/health.spec.ts › API здоровья отвечает 200 и не кэшируется
- Сайт не индексируется поисковиками → e2e/health.spec.ts › сайт не индексируется
- Задачи по расписанию запускаются только с секретом планировщика → e2e/health.spec.ts › запуск задач по расписанию требует секрет планировщика
