# Buhuchet.kg — Стандарт Дизайн-Системы и UX/UI Руководство

**Версия:** 1.0.0  
**Статус:** Официальный стандарт разработки  
**Назначение:** Единый регламент проектирования, верстки и архитектуры пользовательских и административных интерфейсов платформы **Buhuchet.kg**.

---

## 1. ФИЛОСОФИЯ И ПРИНЦИПЫ ИНТЕРФЕЙСА

Платформа **Buhuchet.kg** предназначена для бухгалтеров, руководителей и бизнесменов Кыргызстана. Главные приоритеты интерфейса:

1. **Скорость и предсказуемость**: Единое поведение элементов во всех модулях. Пользователь, освоивший один модуль (например, «Реестр файлов»), должен мгновенно ориентироваться в любом другом («Контрагенты», «Сотрудники», «Супер-админка»).
2. **Нулевой инженерный сленг (Строгий Глоссарий)**:
   - ❌ **ЗАПРЕЩЕНО** использовать технические аббревиатуры и термины в интерфейсах: `R2`, `S3`, `B2B`, `CoW`, `Copy-on-Write`, `RLS`, `SQL`, `UUID`, `Null`, `Undefined`, `DB`.
   - ✅ **ОБЯЗАТЕЛЬНО** использовать понятные бизнес-термины: «Облачный диск», «Реестр документов», «Контрагенты», «Общий доступ», «Прикрепленные файлы», «Статус периода», «Организация».
3. **Бесшовная Кроссплатформенность (ПК + Мобильные)**:
   - Все интерфейсы обязаны корректно отображаться на мониторах (1920px+), ноутбуках (1366px), планшетах (768px-1024px) и смартфонах (<768px).
   - На смартфонах таблицы трансформируются в карточки, а модальные окна становятся снизу выдвигающимися шторками (Bottom Sheets).
4. **100% Компонентная Унификация**:
   - Категорически запрещено верстать уникальные кастомные макеты страниц (`page.tsx`) с нуля. Все страницы строятся исключительно на базе универсальных каркасов из `components/ui/unified/`.

## 2. ЦВЕТОВАЯ ПАЛИТРА И ТИПОГРАФИКА (DESIGN TOKENS)

### 2.1 Цветовые токены (Dark / Light Theme)
Система использует адаптивную тёмно-синюю тему по умолчанию (оптимизирована для длительной работы бухгалтеров):

| Назначение | CSS Переменная / Класс Tailwind | HEX (Dark Mode) | Описание |
| :--- | :--- | :--- | :--- |
| **Основной фон** | `bg-background` | `#0B0F19` | Глубокий темный фон приложения |
| **Фон карточек/панелей** | `bg-card` / `bg-slate-900` | `#111827` | Поверхность блоков и модальных окон |
| **Границы и разделители** | `border-border` / `border-slate-800` | `#1F2937` | Тонкие контрастные границы |
| **Первичный акцент** | `bg-primary` / `bg-blue-600` | `#2563EB` | Главные кнопки, активные состояния |
| **Успех / Обработан** | `bg-emerald-500/10` `text-emerald-400` | `#10B981` | Статусы «Верифицирован», «Проведён» |
| **Предупреждение / Ожидание**| `bg-amber-500/10` `text-amber-400` | `#F59E0B` | Статусы «Черновик», «На проверке» |
| **Ошибка / Удаление** | `bg-rose-500/10` `text-rose-400` | `#EF4444` | Деструктивные действия, блокировка |

### 2.2 Тач-зоны и размеры на смартфонах
- **Минимальная область нажатия (Touch Target)**: На мобильных устройствах (<768px) любые интерактивные элементы (кнопки, иконки, строки) обязаны иметь минимальную высоту и ширину **44px–48px** во избежание фантомных кликов.

## 3. БАЗОВЫЕ УНИВЕРСАЛЬНЫЕ UI-КОМПОНЕНТЫ

### 3.1 `UnifiedWorkspaceLayout` (Стандартный макет рабочей области)
**Назначение**: Главный каркасный компонент для всех страниц реестров как в учётке (`app/dashboard/*`), так и в супер-админке (`app/super-admin/*`).

```tsx
import { UnifiedWorkspaceLayout } from "@/components/ui/unified/UnifiedWorkspaceLayout";

<UnifiedWorkspaceLayout
  title="Реестр документооборота"
  description="Товарные накладные, акты выполненных работ и счета-фактуры КР"
  badge={{ text: "Активный период", variant: "success" }}
  actionButtons={
    <Button onClick={handleCreate}>+ Создать документ</Button>
  }
  tabs={[
    { id: "all", label: "Все документы", count: 12 },
    { id: "incoming", label: "Входящие", count: 5 },
    { id: "outgoing", label: "Исходящие", count: 7 },
  ]}
  activeTab={activeTab}
  onTabChange={setActiveTab}
  filterSlot={<DocumentFilters />}
>
  <UnifiedDataGrid ... />
</UnifiedWorkspaceLayout>
```

**Правила поведения**:
- На ПК: Отображает шапку, кнопку создания справа, вкладки и фильтры в одну строку.
- На смартфонах (<768px): Кнопка создания переносят вниз или в FAB (Floating Action Button), фильтры сворачиваются в гармошку, а вкладки получают горизонтальный скролл (Touch Scroll).

---

### 3.2 `UnifiedViewModal` (Универсальная форма просмотра записи)
**Назначение**: Единственный стандарт карточки просмотра информации по любой записи (файлу, документу, контрагенту, сотруднику, организации).

```tsx
import { UnifiedViewModal } from "@/components/ui/unified/UnifiedViewModal";

<UnifiedViewModal
  isOpen={isOpen}
  onClose={() => setIsOpen(false)}
  title={`Документ № ${doc.number}`}
  subtitle={`Составлен: ${doc.date}`}
  badge={{ text: doc.statusLabel, variant: doc.statusVariant }}
  sections={[
    {
      title: "Основная информация",
      fields: [
        { label: "Вид документа", value: doc.type },
        { label: "Контрагент", value: doc.counterpartyName },
        { label: "Сумма", value: `${doc.amount} с.` },
      ]
    },
    {
      title: "Прикрепленные файлы",
      fields: [
        { label: "Файл скана", value: doc.fileName, isLink: true, onClick: handleDownload }
      ]
    }
  ]}
  previewSlot={<ScanViewer fileUrl={doc.scanUrl} />}
  actions={[
    { label: "Скачать", icon: DownloadIcon, onClick: handleDownload, variant: "outline" },
    { label: "Редактировать", icon: EditIcon, onClick: handleEdit, variant: "secondary" },
    { label: "Удалить", icon: TrashIcon, onClick: handleDelete, variant: "destructive" },
  ]}
/>
```

**Правила конструкции**:
1. **Шапка**: Название объекта, подзаголовок с датой/автором, статусный цветной Badge, верхний крестик закрытия `X`.
2. **Центральный блок**: Сетка полей (1 колонка на мобильном, 2-3 на ПК), разбитая на логические секции.
3. **Preview Slot (Опционально)**: Встроенный предпросмотр сканов, PDF или файлов.
4. **Фиксированный подвал (Action Bar)**: Панель основных действий. На смартфонах прилипает к низу экрана.

---

### 3.3 `UnifiedDataGrid` (Универсальный реестр данных и таблица)
**Назначение**: Таблица с поддержкой сортировки, пагинации, поиска и автоматической трансформой в мобильные карточки.

**Требования**:
- При клике на строку таблицы (`onRowClick`) **ОБЯЗАТЕЛЬНО** вызывается либо `UnifiedViewModal`, либо открывается детальная страница сущности.
- Строго контролировать передачу валидного `id` (запрет на `undefined`).

---

### 3.4 `UnifiedSidebar` (Модульное левое меню)
**Назначение**: Главное навигационное меню приложения.

**Изоляция ролей**:
- **Учётная часть (`/dashboard/*`)**: Показывает пользовательские модули: «Главная Панель», «Реестр документов», «Облачный диск», «Контрагенты», «Сотрудники», «Профиль организации», «Подписка и баланс».
- **Супер-Админка (`/super-admin/*`)**: Показывает ТОЛЬКО служебные модули: «Организации», «Пользователи», «Служебный реестр файлов», «Telegram-боты», «Инспектор БД», «Подписки».
- **Категорически запрещено** смешивать элементы меню организации в панели супер-администратора!

---

### 3.5 `UnifiedHeader` & `UnifiedBottomNav`
- **`UnifiedHeader`**: Верхняя панель с выбором активной организации, профилем пользователя и кнопкой открывания мобильного меню.
- **`UnifiedBottomNav`**: Нижняя плашка навигации для смартфонов (<768px) с большими иконками главных модулей.

---

### 3.6 Стандарт Skeleton-экранов (`loading.tsx`)
Во всех маршрутных директориях Next.js App Router (`/dashboard/**/loading.tsx`, `/super-admin/**/loading.tsx`) обязательно размещаются файлы `loading.tsx`, обеспечивающие мгновенный отклик при переходе между вкладками:
- Использование пульсирующей анимации `animate-pulse` с токенами `bg-muted/60` и `bg-card/60`.
- Воспроизведение структуры целевого экрана: шапка страницы, карточки KPI/метрик и строки реестра данных.

## 4. СТАНДАРТЫ UX FEEDBACK И ОБРАБОТКИ ОШИБОК

1. **Никаких нативных `window.alert()`**:
   - ❌ Использование `alert("Ошибка")` **строго запрещено**.
   - ✅ Все сообщения высылаются через стилизованные уведомления: `toast.error("Сообщение")` или `toast.success("Успешно")`.
2. **Skeleton-лоадеры вместо пустых экранов**:
   - При загрузке данных в карточках просмотра или таблицах отображается анимация загрузки (Skeleton), повторяющая форму контента.
3. **Безопасное закрытие при ошибках**:
   - Если Server Action возвращает ошибку «Запись не найдена», модальное окно должно автоматически закрываться с выводом плавающего toast-уведомления.

- [ ] Команда `npm run build` проходит успешно.
