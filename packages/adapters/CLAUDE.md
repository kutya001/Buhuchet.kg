# packages/adapters — переходники

Всё, что зависит от поставщика (Vercel, Supabase, Telegram, S3), живёт только здесь. При переезде на VPS меняются эти файлы и переменные окружения, остальной код не трогаем.

- `config` — единственное место, где читается `process.env`; схема Zod, приложение не стартует без нужных настроек.
- `clock` — «сейчас» и «сегодня по Бишкеку»; в тестах и демо время фиксируется (`fixedClock`, `FIXED_NOW`).
- `storage` — файлы по протоколу S3 (Supabase Storage, MinIO, Cloudflare R2); путь `org/<org_id>/<раздел>/<id>`; скачивание только по временной подписанной ссылке.
- `scheduler` — разбор расписаний (по времени Бишкека), поиск «пропущенного» запуска, проверка секрета вызова, цикл worker; Vercel Cron только будит маршрут `/api/cron/tick` раз в минуту.
- `telegram` — отправка сообщений и проверка секрета вебхука; в тестах — `createFakeTelegram`.
- `logger` — pino в стандартный вывод, секреты вычищаются.

Правила:
- `@supabase/*` и `@vercel/*` разрешены только в этом пакете (ESLint и `pnpm check:portability`); сейчас они не нужны вовсе.
- У каждого переходника есть интерфейс и «поддельная» реализация для тестов остальных пакетов.
- Тесты против настоящего S3 (MinIO) запускаются, когда заданы переменные `S3_*`; в CI они обязательны (`REQUIRE_INTEGRATION_TESTS=1`).
