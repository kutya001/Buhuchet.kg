# packages/adapters — переходники

Всё, что зависит от поставщика (Vercel, Supabase, Telegram, S3), живёт только здесь. При переезде на VPS меняются эти файлы и переменные окружения, остальной код не трогаем.

- `config` — единственное место, где читается `process.env`; схема Zod, приложение не стартует без нужных настроек.
- `clock` — «сейчас» и «сегодня по Бишкеку»; в тестах и демо время фиксируется (`fixedClock`, `FIXED_NOW`).
- `storage` — файлы по протоколу S3 (Supabase Storage, MinIO, Cloudflare R2); путь `org/<org_id>/<раздел>/<id>`; скачивание только по временной подписанной ссылке. Загрузка из браузера — `signedUploadUrl` (в подписи размер и тип), проверка после неё — `stat`. Ссылки для браузера подписываются по `S3_PUBLIC_ENDPOINT` (пусто — `S3_ENDPOINT`).
- `scheduler` — разбор расписаний (по времени Бишкека), поиск «пропущенного» запуска, проверка секрета вызова, цикл worker; Vercel Cron только будит маршрут `/api/cron/tick` раз в минуту.
- `telegram` — отправка сообщений и проверка секрета вебхука; в тестах — `createFakeTelegram`. Сообщение бота (docs/decisions.md п. Т-1): `sendMessage` с `options.keyboard` (ряды кнопок: действие `data`, копирование `copy`, ссылка `url`, неактивная `disabled`), `options.rich` (вид с таблицами — `sendRichMessage`; не принят сервером — тот же текст обычным сообщением) и `options.code` (код в тексте — моноширинный); `answerCallback` — скрытый ответ на нажатие, `editKeyboard` — кнопки после нажатия. Токен бота из текста ошибки сети вычищает сам переходник (`redactBotToken`), исходную ошибку причиной не передаёт. Подставной бот хранит `sent`, `messageIds` (номер сообщения для `sent[i]`), `answers`, `edits`. Файл, присланный боту (задача Т2), — `loadFile(fileId, maxBytes)`: `getFile` и скачивание с пределом размера (и заявленного, и фактического), путь от Telegram проверяется, адрес с токеном наружу не отдаётся, сбой — `{ ok: false, reason: 'too_large' | 'failed' }` с вычищенным текстом; в подставном боте файлы — `files` (номер файла → содержимое). Меню команд (задача Т5): `setCommands(commands)` — меню бота для личных чатов (`setMyCommands`), `options.menu` — кнопки под полем ввода (ряды подписей; пустой список — убрать; вместе с `keyboard` не передаётся — Telegram принимает одну разметку); в подставном боте — `commands`. Виджет (задача Т9, Bot API 10.4): `sendWidget(chatId, { html, chatData, caption, threadId? })`, `editWidgetData` (меняются только данные; «not modified» — успех), `answerWidgetQuery`; в подставном боте — `widgets`, `widgetEdits`, `widgetAnswers`.
- `logger` — pino в стандартный вывод, секреты вычищаются.
- `documents` — чтение PDF «Из свидетельства и выписки» (вход `@buhuchet/adapters/documents`, грузится при первом вызове): текстовый слой — pdf.js, нет текста — распознавание картинки tesseract.js (rus + kir, языки из `@tesseract.js-data/*`, без сети); пределы — страницы, время, знаки; в тестах — `createFakeDocumentReader`. Новый файл библиотеки, который нужен в работе, — в `outputFileTracingIncludes` `apps/web/next.config.ts`, иначе его не будет в сборке `standalone` (docs/decisions.md, п. А-8).

Правила:
- `@supabase/*` и `@vercel/*` разрешены только в этом пакете (ESLint и `pnpm check:portability`); сейчас они не нужны вовсе.
- У каждого переходника есть интерфейс и «поддельная» реализация для тестов остальных пакетов.
- Тесты против настоящего S3 (MinIO) запускаются, когда заданы переменные `S3_*`; в CI они обязательны (`REQUIRE_INTEGRATION_TESTS=1`).
