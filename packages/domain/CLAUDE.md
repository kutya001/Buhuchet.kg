# packages/domain — бизнес-правила

- Чистый TypeScript: никакой базы, сети, файлов, времени «сейчас» и фреймворков. Нельзя импортировать `@buhuchet/db`, `@buhuchet/adapters`, `@buhuchet/api`, `hono`, `drizzle-orm`, `postgres`, `node:*` (проверяет ESLint).
- «Сегодня» и «сейчас» приходят параметром (их даёт `clock` из `@buhuchet/adapters`), поэтому любая функция проверяется тестом с фиксированной датой.
- Деньги — целые тыйыны (`number`, `Number.isSafeInteger`), на экран — через `formatSom`. Дробные сомы в расчётах не держим.
- Даты сроков — строки `YYYY-MM-DD` (тип `IsoDate`), считаются по Бишкеку (UTC+6).
- Источник правил — раздел ТЗ модуля в `spec/` и файлы прототипа `spec/prototype/src/js/core/*.js`, `spec/prototype/src/js/modules/*.js`. Эталонные ответы для тестов берутся из прототипа (скилл `prototype-oracle`).
- Порог покрытия тестами — 80 % (`pnpm --filter @buhuchet/domain test:coverage`); падение ниже останавливает слияние.
- Тексты экранов по умолчанию (начальное наполнение словаря) — `UI_TEXTS` в `src/l10n/texts.ts`, тексты модуля — своим файлом `src/l10n/<модуль>-texts.ts` (в `texts.ts` — одна строка модуля); сообщения правил домена (ошибки проверок) пока остаются в модулях домена (docs/decisions.md, п. 24).
- Файлы раскладываются по модулям ТЗ: `src/<модуль>/…` (`reports`, `contractors`, `money`, …); общие кирпичи — в `src/common/`.
- Списки — `src/common/list.ts`: размеры страниц и «Все записи» (не больше 5 000 строк), `pageCount`, `shownRange`, сортировка по кругу `nextSort`, типы столбцов и фильтров, поиск как в прототипе `matchesSearch` (эталон для SQL), группировка `toggleGroupLevel` / `groupLevels` и итоги групп `groupAggOf` (по умолчанию сумма у числовых), предел выгрузки `EXPORT_ROWS_LIMIT`, настройки вида `GridViewSettings`, ключи списков `GRID_KEYS` (новый список с настройками вида — новый ключ) и «Статистики» модуля `statsViewKey` / `statsShown` (`isViewKey` — оба вида), формы числа `pluralForm`, число с разрядами `formatCount`.
- Шкалы статусов — `src/common/status.ts` (прототип `ui/status-scale.js`): `STATUS_SCALE_DEFS` (шаги, боковые, «Не требуется», отметки, цвет и значок), `scalePosition`, `scaleNext`, `scaleBack`, `rollbackRefusal`, `statusDurations`, `statusTotals`, `durationText`; названия статусов — ключи словаря `status.<шкала>.<код>` (`src/l10n/status-texts.ts`). Ответы сверены с прототипом: `scripts/oracle-status.mjs` пишет `src/common/__fixtures__/status-scales.json`.
- Справочники платформы — `src/platform-dicts/`: списки значений каталога (`catalog.ts`: виды периодичности, действия, группы выбора, режимы, льготы, …) и производственный календарь (`calendar.ts`, прототип `core/reference.js`): `productionCalendar`, `isWorkingDay`, `nextWorkingDay` (перенос срока с выходного), `calendarYear` (дни года для ответа API), `calendarEntryProblem` (проверка записи при наполнении). Ответы сверены с прототипом: `scripts/oracle-calendar.mjs` пишет `src/platform-dicts/__fixtures__/calendar.json`.
- Справочники организации — `src/dicts/`: сроки словами (`report-types.ts`: `dueRuleText`, `payRuleText`, `paysText`, прототип `ruleText`, `payRuleText`), правила подключения и настроек вида (`org-report-types.ts`: `orgReportTypeProblem`), группы окна «Выбор налогов» (`tax-pick.ts`: `taxPickGroups`, `mainTaxPicks`, прототип `txGroups`, `txMain`). «Справочники платформы» для организации (`platform-dicts.ts`): плитки по группам (`orgDictGroups`), столбцы окон (`ORG_DICT_COLUMNS`), справочники «Поиска по всем значениям» (`ALL_VALUES_DICTS`), справочники запроса «Попросить добавить» (`DICT_REQUEST_DICTS`); описания значений (`value-guide.ts`: «Меняет сроки» льготы `benefitDueText`, строки суммы ставки ЕН `singleTaxRateParts`, прототип `benOvTxt`, `rtParts`). Ответы сверены с прототипом: `scripts/oracle-report-rules.mjs`, `scripts/oracle-tax-pick.mjs` и `scripts/oracle-value-guide.mjs` пишут `src/dicts/__fixtures__/`.
- Контрагенты — `src/contractors/`: правила полей и сохранения (`rules.ts`: `innProblem`, `innDuplicateMessage`, `contractorFieldProblems`, `contractorDeleteRefusal`, `parseContract`) и сверка с ГКЭД (`gked.ts`, прототип `gkCheck`: `gkedCheck` — запрет режима, вопрос о праве на режим, льготы, подсказка ставки ЕН, отчёты и отключённые коды; `gkedCheckTexts` — словами; `gkedSignature` — к чему привязано подтверждение). Ответы сверены с прототипом: `scripts/oracle-gked.mjs` пишет `src/contractors/__fixtures__/gked.json` (69 случаев, в том числе п. 17, 18, 56–58 приёмки).
- Тариф Соцфонда — `src/contractors/socfund.ts` (прототип `core/socfund.js`, `modules/socfund-ui.js`, эталон `scripts/oracle-socfund.mjs`): `socfundNeeded`, `socfundAuto`, `socfundState` и тексты причин, сохранение формы `socfundDecide` (причина и подтверждение — `socfundManualMismatch`, `socfundConfirmText`), строки истории, подсказка о пене `penaltyText`; тариф и по действующему STI-161 без основания — `SOCFUND_BY_REPORT = true` (решение заказчика, docs/deviations.md п. А-5).
- Отчёты — `src/reports/`: периоды (`periods.ts`: `periodStartOf`, `periodWindow`, `pastPeriods`, `periodLabel`, `dateOf` — число больше дней месяца даёт последний день), сроки (`due.ts`: `effectiveRule` — правило вида, срок статуса и назначения, `reportDue` — срок сдачи и оплаты с переносом по календарю, `periodsDue`, `defaultAssignmentFrom`, `ASSIGNMENT_DUE_DAYS`), ставки словами (`rates.ts`: `assignmentRateText`), правила отчётов (`rules.ts`: снятие и возврат назначения, незавершённые, `revisionDue`, `REPORT_MESSAGES`) и проверка назначения (`assignment.ts`: `assignmentProblem`). Эталон прототипа — `scripts/oracle-due.mjs` и `oracle-rates.mjs` (`src/reports/__fixtures__`).
- Деньги — `src/money/requisites.ts` (прототип `core/requisites.js`): виды реквизита и назначения счёта, проверка `requisiteProblems` (в форме и на сервере), `normalizeRequisite`, строки для экрана (`requisiteText`, `requisiteNumberText`), «Основной» (`orgAccountMains`, `walletMains`, прототип `rqMainFix`), выбор банков (`bankChoices`), реквизиты для налогов контрагента (`taxRequisiteChoices`, `mainTaxRequisite`) и предупреждение при удалении последнего счёта для налогов (`lastTaxAccountWarning`).
- Деньги по отчётам — `src/money/tax.ts` (прототип `core/derive.js`, `core/org.js` `schedule`, `ui/status-scale.js`, вкладка «Деньги» карточки контрагента): статус оплаты (`paymentStatus`, у «Уплаты» — `payOnlyReportStatus`), график оплаты долями (`scheduleDues`, `paymentSchedule`, `schedulePayDue`), просрочка оплаты (`paymentOverdue`), остаток денег контрагента (`fundsBalance`), отложено под отчёт и «Оплачено / Достаточно / Недостача» (`contractorMoney`), «Сдан» только после оплаты (`submitNeedsPayment`, `submitPaymentReason`), окно «Отметить оплаченным» (`paymentDefaults`, `paymentProblem`, `paymentProblemText`), сверка за месяц (`monthReconciliation`) и «Свободного остатка нет» (`noFreeBalanceReason`). Ответы сверены с прототипом: `scripts/oracle-money.mjs` пишет `src/money/__fixtures__/tax.json`.
- Плата за обслуживание — `src/fees/` (docs/decisions.md, п. В-7; прототип `core/org.js`, `modules/contractor-card.js`, `ui/status-scale.js` `waDlg`; месяцы — `src/common/months.ts`): журнал тарифов и окно «Новая ставка» (`tariffs.ts`: `tariffAt`, `currentTariff`, `tariffDefaults`, `tariffProblem`), месяцы с начислением, начисление с первым неполным месяцем, срок оплаты, оплаты по месяцам, аванс, долг, статус и «просрочено» месяца, «Принять оплату» и напоминание о долге (`charges.ts`: `feeMonths`, `feeCharge`, `feeDue`, `paidByMonth`, `advanceSplit`, `contractorFees`, `canAcceptFeePayment`, `feeReminder`), окно «Принять оплату за обслуживание» (`payment.ts`: `feePaymentForm`, `autoAllocate`, `allocationRowState`, `allocationBalance`, `feePaymentProblem`, `allocationText`), текст напоминания (`reminder.ts`: `FEE_WHATSAPP_TEMPLATE`, `feeWhatsAppText`), отказы (`messages.ts`: `FEE_MESSAGES`). Начисления не хранятся — считаются из журнала тарифов и периодов обслуживания. Ответы сверены с прототипом: `scripts/oracle-fees.mjs` пишет `src/fees/__fixtures__/fees.json`.
- Показатели контрагентов — `src/kpi/` (прототип `modules/kpi.js`): месяцы `YYYY-MM` (общие: `src/common/months.ts`), поля и проверка окна показателя, разбор и показ значения, итоги (`indicators.ts`: `indicatorProblems`, `parseIndicatorValue`, `indicatorValueText`, `indicatorTotals`; значение — целые сотые), кому и за какие месяцы показатель обязателен, срок и статус месяца, «Не заполнено», счётчик, статистика (`fill.ts`: `indicatorApplies`, `monthIndicators`, `fillDue`, `nextFillStatus`, `missingMonths`, `missingSummary`, `fillStats`), «Кому вести» (`targets.ts`: `toggleTarget`, `applyWho`), ввод из Excel (`excel.ts`: `importTemplate`, `planImport`, `importWrites`, заголовок столбца `importHead`, пределы `KPI_IMPORT_MAX_*`). Ответы сверены с прототипом: `scripts/oracle-kpi.mjs` пишет `src/kpi/__fixtures__/kpi.json`.
- Файлы — `src/files/files.ts` (прототип `modules/files.js`): предел 20 МБ, тип по расширению и запрещённые типы (`fileUploadProblem`, docs/deviations.md п. Г-1), размер словами (`fileSizeParts`, прототип `fmtSize`), удаление своего файла в течение суток (`fileDeleteRefusal`), виды записей-источников `FILE_SOURCE_KINDS`.
- Файловый менеджер — `src/files/manager.ts`: плашки по видам источника (`fileManagerPlates`), значки (`FILE_KIND_ICONS`), тип файла, что показывается в окне (`filePreviewKind`: картинки и PDF). Право шага «Базы знаний», которого нет в справочнике шагов, — `KbStepRule.permission`.
- «База знаний» — `src/kb/`: каталог из refDB.json (`catalog.ts`), программа, процент, уровни, «Новое», экран шага (`program.ts`: `kbProgram`, `kbStats`, `kbNextStep`, `kbStepIsNew`, `kbOnStepScreen`), статьи и поиск (`articles.ts`). Какие шаги уже работают и чем отмечаются — `KB_STEP_RULES` и `KB_READY_MODULES` (`ready.ts`): задача модуля добавляет сюда свои шаги (docs/decisions.md, п. Г-2). «Показать как» и знакомые элементы — `shows.ts` (`kbKnownKey`, `kbSmartList`, `kbStepShowItems`, `kbScreenShowItems`; п. Г-5).
- «Новости» — `src/news/`: типы, видимость (`newsLive`, `newsState`, 09:00 по Бишкеку), порядок и группы по версиям (`compareNews`, `newsGroups`), проверка формы (`newsProblems`) и картинок (`newsImageProblem`), вид записи истории в Админке (`newsHistoryKinds`), разбор markdown в блоки (`markdown.ts`: `newsMdBlocks`, без HTML) — docs/decisions.md, п. Г-3.
- «Приветствие» — `src/onboarding/`: ответы опросника (`onboardingFreshAnswers`, `onboardingAnswersOf`), план «Что будет включено» (`onboardingPlan`, повторно — `onboardingRetakePlan`, docs/deviations.md п. Г-5), переключатель плана (`onboardingPlanToggle`), разница с политикой (`onboardingChanges`), что открыть после входа (`welcomeAtLogin`) и экраны (`welcomeScreens`) — docs/decisions.md, п. Г-4.
