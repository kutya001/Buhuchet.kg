# packages/api — API на Hono

- Не зависит от Next.js: в веб-приложении монтируется одним catch-all роутом `apps/web/app/api/[[...route]]/route.ts`, на VPS может работать отдельно (`src/standalone.ts`, @hono/node-server).
- Входы пакета: `@buhuchet/api/web` — обработчик для сайта (приложение API целиком), `@buhuchet/api/runtime` — зависимости из окружения, `@buhuchet/api/jobs` — `runDueJobs` для worker. Worker собирается в один файл и не должен импортировать приложение API (`createApp`, `src/web.ts`): в нём нативный модуль argon2, который в такой файл не собирается.
- Каждый метод — `createRoute` из `@hono/zod-openapi` со схемами Zod из `@buhuchet/shared` для входа и выхода; описание OpenAPI строится само: `/api/openapi.json`.
- Маршруты раскладываются по модулям ТЗ: `src/modules/<модуль>/…`; модуль экспортирует функцию, которая регистрирует свои маршруты (пример — `src/modules/system`).
- Зависимости (база, хранилище, часы, журнал, Telegram, настройки) приходят через `ApiDeps` (`src/deps.ts`); в тестах — поддельные (`src/testing.ts`). `process.env` здесь не читается — только `loadConfig` в `src/runtime.ts`.
- Общий слой (`src/middleware/`, подключён в `app.ts` для всех путей): `originCheck` — изменяющий запрос (всё, кроме GET, HEAD, OPTIONS) только с Origin нашего адреса (`APP_BASE_URL` или Host); `sessionGuard` — cookie → сеанс → организация: без сеанса 401, блокировка — 403 и сеанс закрывается, с временным паролем — только `/api/auth/me` и `/api/auth/password`; права сотрудника лежат в `c.var.access`, сеанс — в `c.var.session`. Открытые пути (без входа) перечислены в `PUBLIC_PATHS` (`middleware/session.ts`) — новый открытый метод добавляется туда явно; без Origin принимаются только `/api/cron/*` и вебхук Telegram — у них свой секрет в заголовке.
- Право метода — `middleware: [requirePermission('<право>')] as const` в `createRoute` (403 `forbidden`); метод для любого сотрудника — `requireEmployee`; метод Админки — `requirePlatformAdmin`. Область «Свои / Все контрагенты» — `scopeOf(c.var.access.subject, '<группа>')`, условие — в запрос.
- Данные организаций — только через `withOrgContext(deps.db, orgContextOf(c), …)` из `@buhuchet/db` (RLS): организация и автор берутся из сеанса, никогда из тела или параметров запроса; без организации в сеансе `orgContextOf` отвечает 403.
- Тело запроса — не больше 1 МиБ (`bodyLimit` в `app.ts`); файлы идут в хранилище по подписанной ссылке, мимо API.
- Вход, выход, «кто я», смена пароля, «Забыли пароль?» — модуль `src/modules/auth`; таблицы входа читаются только функциями `app.auth_*` из `@buhuchet/db` (до выбора организации RLS их не показывает). «Забыли пароль?» для любого логина отвечает одинаково и не быстрее `deps.resetResponseFloorMs` (в тестах 0): не добавлять туда ответов, по которым видно, есть ли логин.
- Telegram — модуль `src/modules/telegram`: ссылка привязки, отвязка, вебхук (секрет проверяет `webhookGuard` до разбора тела). Сообщение пользователю сразу, мимо очереди, — `sendNow`, текст — `botText(deps, '<ключ шаблона>', значения)` (шаблон справочника платформы, иначе `TELEGRAM_TEMPLATE_DEFAULTS`); о каждой смене пароля — `notifyPasswordChanged`, о замене и отвязке Telegram — в прежний чат. Код и пароль в журнал не пишутся; ошибка Telegram метод не роняет. Очередь напоминаний — поток Б.
- Ошибки — `{ error: { code, message } }`; `code` — ключ словаря интерфейса. `RecordChangedError` и `RecordNotFoundError` из `@buhuchet/domain` метод не ловит: общий обработчик отвечает 409 `record_changed` («Запись изменена другим пользователем», в `details.version` — текущая версия) и 404 `not_found`. Метод, который сохраняет запись с версией, добавляет в ответы `...versionedSaveResponses` (`src/errors.ts`). Ошибку в журнал — только под ключом `err` (`logger.error({ err }, …)`): так из ошибок запросов к базе вычищаются значения параметров.
- Задачи по расписанию — `src/jobs/registry.ts`: имя, расписание cron по Бишкеку, окно догоняния; задача безопасна при повторе. Запускает их `/api/cron/tick` (Vercel Cron, cron на VPS) или apps/worker — одна и та же функция `runDueJobs`.
- Порог покрытия — 80 % (`pnpm --filter @buhuchet/api test:coverage`). Тесты прав и изоляции организаций — против настоящего PostgreSQL (`createTestDatabase`).
