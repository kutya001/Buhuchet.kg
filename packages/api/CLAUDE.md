# packages/api — API на Hono

- Не зависит от Next.js: в веб-приложении монтируется одним catch-all роутом `apps/web/app/api/[[...route]]/route.ts`, на VPS может работать отдельно (`src/standalone.ts`, @hono/node-server).
- Входы пакета: `@buhuchet/api/web` — обработчик для сайта (приложение API целиком), `@buhuchet/api/runtime` — зависимости из окружения, `@buhuchet/api/jobs` — `runDueJobs` для worker. Worker собирается в один файл и не должен импортировать приложение API (`createApp`, `src/web.ts`): в нём нативный модуль argon2, который в такой файл не собирается.
- Каждый метод — `createRoute` из `@hono/zod-openapi` со схемами Zod из `@buhuchet/shared` для входа и выхода; описание OpenAPI строится само: `/api/openapi.json`.
- Маршруты раскладываются по модулям ТЗ: `src/modules/<модуль>/…`; модуль экспортирует функцию, которая регистрирует свои маршруты (пример — `src/modules/system`).
- Зависимости (база, хранилище, часы, журнал, Telegram, настройки) приходят через `ApiDeps` (`src/deps.ts`); в тестах — поддельные (`src/testing.ts`). `process.env` здесь не читается — только `loadConfig` в `src/runtime.ts`.
- Общий слой (`src/middleware/`, подключён в `app.ts` для всех путей): `originCheck` — изменяющий запрос (всё, кроме GET, HEAD, OPTIONS) только с Origin нашего адреса (`APP_BASE_URL` или Host); `sessionGuard` — cookie → сеанс → организация: без сеанса 401, блокировка — 403 и сеанс закрывается, с временным паролем — только `/api/auth/me` и `/api/auth/password`; права сотрудника лежат в `c.var.access`, сеанс — в `c.var.session`. Открытые пути (без входа) перечислены в `PUBLIC_PATHS` (`middleware/session.ts`) — новый открытый метод добавляется туда явно; без Origin принимаются только `/api/cron/*` и вебхук Telegram — у них свой секрет в заголовке.
- Право метода — `middleware: [requirePermission('<право>')] as const` в `createRoute` (403 `forbidden`); метод для любого сотрудника — `requireEmployee`; метод Админки — `requirePlatformAdmin`. Область «Свои / Все контрагенты» — `scopeOf(c.var.access.subject, '<группа>')`, условие — в запрос.
- Данные организаций — только через `withOrgContext(deps.db, orgContextOf(c), …)` из `@buhuchet/db` (RLS): организация и автор берутся из сеанса, никогда из тела или параметров запроса; без организации в сеансе `orgContextOf` отвечает 403.
- Тело запроса — не больше 1 МиБ (`bodyLimit` в `app.ts`); файлы идут в хранилище по подписанной ссылке, мимо API. Исключение — логотип организации (до 2 МБ, `OWN_BODY_LIMIT_PATHS`): метод сам ставит предел и проверяет, что это PNG или JPG, до сохранения.
- Вход, выход, «кто я», смена пароля, «Забыли пароль?» — модуль `src/modules/auth`; таблицы входа читаются только функциями `app.auth_*` из `@buhuchet/db` (до выбора организации RLS их не показывает). Вход для неизвестного логина и неверного пароля отвечает одинаково («Неверный логин или пароль», пароль неизвестного логина сверяется с подставным хешем), «вход закрыт» наступает одинаково для любого логина, о блокировке сотрудника и организации — только после верного пароля; «Забыли пароль?» для любого логина отвечает одинаково и не быстрее `deps.resetResponseFloorMs` (в тестах 0). Не добавлять в эти методы ответов, по которым видно, есть ли логин (docs/deviations.md, п. 4).
- Telegram — модуль `src/modules/telegram`: ссылка привязки, отвязка, вебхук (секрет проверяет `webhookGuard` до разбора тела; адрес вебхука сайт сообщает Telegram сам — задача `telegram.register-webhook` из `jobsFor(config)`). Сообщение пользователю сразу, мимо очереди, — `sendNow`, текст — `botText(deps, '<ключ шаблона>', значения)` (шаблон справочника платформы, иначе `TELEGRAM_TEMPLATE_DEFAULTS`); о каждой смене пароля — `notifyPasswordChanged`, о замене и отвязке Telegram — в прежний чат. Код и пароль в журнал не пишутся; ошибка Telegram метод не роняет. Очередь напоминаний — поток Б.
- Ошибки — `{ error: { code, message } }`; `code` — ключ словаря интерфейса. Запрос к базе дольше предела вида работы общий обработчик отвечает 503 `query_timeout` (у методов списка — в `listQueryResponses`). `RecordChangedError` и `RecordNotFoundError` из `@buhuchet/domain` метод не ловит: общий обработчик отвечает 409 `record_changed` («Запись изменена другим пользователем», в `details.version` — текущая версия) и 404 `not_found`. Метод, который сохраняет запись с версией, добавляет в ответы `...versionedSaveResponses` (`src/errors.ts`). Ошибку в журнал — только под ключом `err` (`logger.error({ err }, …)`): так из ошибок запросов к базе вычищаются значения параметров.
- Сотрудники — модуль `src/modules/staff`, роли и справочник прав — `src/modules/roles` (право «Сотрудники и роли», список и карточка сотрудников — «Просматривать сотрудников»). Правила ролей не пишутся в обработчике: `staffActionRefusal`, `newEmployeeRoleRefusal`, `roleChangeProblem`, `roleDeleteRefusal`, `copiedRolePermissions` из `@buhuchet/domain` (актор — `staffActor(c)`: его права и область для «не выдаёт больше своего») — те же, что у формы роли (docs/deviations.md, п. 15). Отказ по правилу внутри транзакции — `apiFail(статус, код, текст)` из `src/errors.ts`: транзакция откатывается, отвечает общий обработчик; статус — из описания маршрута.
- «Локализация» — модуль `src/modules/l10n`: `GET /api/l10n` без входа, тексты `ui_texts` поверх `UI_TEXTS`, кэш в памяти, сверка с отметкой базы (`uiTextsStamp`) не чаще раза в секунду, ETag и 304; база недоступна — тексты по умолчанию без кэша.
- «Моя организация» — модуль `src/modules/org`: «Основное» с логотипом и адресом страницы, учётная политика и настройки с историей. Видят все сотрудники (`requireEmployee`), меняет право `org`. Правила — `slugProblem`, `featureChangeProblem`, `logoProblem` из `@buhuchet/domain`; логотип наружу — только подписанная ссылка на 15 минут (`logoLink`), отдельным полем ключ хранилища не отдаётся; меню модулей в «кто я» — `menuModules` (функции учётной политики и права). Метод модуля, который выключается в учётной политике, проверяет функцию на сервере (`orgFeatures`), а не только прячет кнопку.
- Метод списка: `request: { query: ListQueryParams }`, в ответах `...listQueryResponses`, в обработчике `listQueryOf(c.req.valid('query'))` и функция страницы из `@buhuchet/db` (`selectListPage`); ответ — `listPageSchema(<запись>)` из `@buhuchet/shared` (`items`, `total`, `page`, `size`, `totals`, у сгруппированного — `groups` и `rowGroups`). Неизвестный столбец в сортировке, фильтре, поиске или группировке — 400 `validation_failed`. Рядом с методом списка — значения столбца для фильтра-галочек `GET …/values?col=` (`ListValuesQuery` → `ListValues`, функция модуля на `selectListValues` из `@buhuchet/db`) и выгрузка `GET …/export` (`ListExportParams`: параметры списка и `cols` — видимые столбцы по порядку экрана; права — просмотр модуля и «Выгружать в Excel»; после `listQueryOf` всё — внутри `withExportSlot(deps, userId, …)`: одна выгрузка пользователя одновременно и не больше 20 за час, иначе 429, в ответах `...exportRateResponses`; запрос к базе — `withOrgContext(…, { ...orgContextOf(c), kind: 'export' })`; ответ — `xlsxResponse` и `xlsxContent` из `src/lists/export.ts`, файл собирает `src/lists/xlsx.ts`); подписи значений-кодов и заголовки файла — тексты словаря `serverTexts(deps)` (`src/modules/l10n/texts.ts`). Пример — `src/modules/staff/employees.ts`. Настройки вида списков — модуль `src/modules/views` (`GET /api/view-settings`, `PUT` и `DELETE /api/view-settings/{ключ}`, только ключи `isViewKey`: списки из `GRID_KEYS` и «Статистика» модуля `stats.<модуль>`).
- Справочники платформы — модуль `src/modules/platform-dicts` (только чтение, любой вошедший — `asSessionUser`): коды телефонов, `GET /api/report-types`, `/tax-regimes`, `/tax-benefits`, `/report-bases`, `/tax-offices`, `/authorities`, `/ownership-forms`, `/single-tax-rates`, `/due-change-reasons` (без `all=true` — только действующие: отключённое значение не предлагается в новых записях; `all=true` — для уже созданных записей и Админки) и `GET /api/production-calendar?year=` (праздники, переносы и рабочие субботы года, `calendarYear`). Правка — Админка (поток Д).
- Справочники организации — модуль `src/modules/dicts` (docs/decisions.md, п. 40): «Виды отчётов» — `GET /api/org-report-types` (список каталога с настройками организации, `values`, `export`), `GET …/settings` (настройки по всем видам и дни учётной политики), `PUT …/{code}` (подключить, отключить, дни, файл, квитанция; с версией) и `POST …/connect` («Выбор налогов»: подключить отмеченные, отключить снятые в одной транзакции). Видят все сотрудники, меняют — право `dicts`; правила — `orgReportTypeProblem` из `@buhuchet/domain`. «Налоги и ставки» — `GET /api/taxes` в `platform-dicts` (`items` и `gkedNames`). «Справочники платформы» (docs/decisions.md, п. 41): `GET /api/platform-dicts` (плитки), `GET /api/platform-dicts/{id}` (окно справочника, `values`, `export`), `GET /api/platform-values` («Поиск по всем значениям», `values`, `export`), `POST` и `GET /api/dict-requests` («Попросить добавить» и «Мои запросы»); всё — любому сотруднику организации (`requireEmployee`), «В Excel» — по праву `export`.
- Файлы записей — модуль `src/modules/files` (docs/decisions.md, п. 43): `GET /api/files?kind&id` (блок «Файлы»), `POST /api/files/uploads` (начать: подписанная ссылка `PUT` в хранилище), `POST /api/files/{id}/complete` (проверить размер, показать, история), `GET …/{id}/link` и `…/{id}/download` (ссылка на 15 минут), `DELETE …/{id}?version`. Модуль с блоком «Файлы» регистрирует источник: вид в `FILE_SOURCE_KINDS` (`@buhuchet/domain`) и строка в `FILE_SOURCES` (`sources.ts`) — `resolve` находит запись с областью своего модуля, `editable`, куда писать историю. В тестах свои источники — `deps.fileSources`. Сутки для удаления своего файла — по настоящим часам, не `deps.clock`. Незаконченные загрузки убирает задача `files.cleanup-pending`.
- Задачи по расписанию — `src/jobs/registry.ts`: имя, расписание cron по Бишкеку, окно догоняния; задача безопасна при повторе; данные организации — в `withOrgContext(ctx.db, { orgId, kind: 'job' })` (предел запроса 4 минуты). Запускает их `/api/cron/tick` (Vercel Cron, cron на VPS) или apps/worker — одна и та же функция `runDueJobs`.
- Порог покрытия — 80 % (`pnpm --filter @buhuchet/api test:coverage`). Тесты прав и изоляции организаций — против настоящего PostgreSQL (`createTestDatabase`).
