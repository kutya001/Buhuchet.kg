# Экран по прототипу

1. Найти экран в прототипе: модуль `spec/prototype/src/js/modules/<модуль>.js`, общие части `spec/prototype/src/js/ui/*.js`, стили `spec/prototype/src/css/*.css`; описание поведения — раздел модуля в ТЗ и «Списки записей» (UnifiedDataGrid). Как устроены экраны — `spec/Основные паттерны разработки.md`.
2. Страница — `apps/web/app/(app)/<модуль>/…`. Данные — только из API типизированным клиентом (`apps/web/src/api-client.ts`) через TanStack Query; формы — React Hook Form + схемы Zod из `@buhuchet/shared`. Никаких Server Actions и запросов к базе.
3. Строить из общих компонентов `packages/ui`: оболочка, список (столбцы, группировка до 2 уровней, фильтры-плашки, плитки на телефоне), карточка с «На весь экран», окна, шкала статусов. Нет нужного — добавить в `packages/ui`, а не в страницу.
4. Тексты — из словаря «Локализация» по ключам; в компонентах строк для людей нет. Деньги — `formatSom`, даты — `formatDateRu` из `@buhuchet/domain`.
5. ПК и телефон: граница 768 px; на телефоне нижняя панель ровно из 4 модулей и «≡ Другие модули», вкладки «N из M ▾», длинные формы — шагами. Кнопок и вкладок без права не показывать (сервер всё равно проверяет).
6. Сохранение записи с версией: ответ 409 (`isRecordChanged`) — правка не сохранена; показать `RecordChangedNotice` из `packages/ui` и по «Перечитать» загрузить запись заново. Молча повторять сохранение с новой версией нельзя.
7. Сквозной тест экрана в `e2e/<модуль>.spec.ts` на desktop и mobile; снимки продукта и прототипа рядом для сверки, заметные отличия — в описание PR.
