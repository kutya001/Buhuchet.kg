# Красный CI

Цель — один заход на исправление, а не по одному падению за прогон: прогон PR идёт ~13 минут, и пока он красный, очередь на слияние стоит у всех потоков. Номера — `docs/typical-mistakes.md`.

## Порядок
1. **Что красное.** Все задания прогона (`check · …`, `e2e N/6`, `pr-policy`), а не первое: итоговые `check` и `docker-e2e` только пересказывают части.
   - «Отменено новым пушем» — не падение, ничего не делать.
   - `pr-policy` у PR Dependabot — норма, пока его не проверил Claude (скилл `dependabot-review`).
   - `pr-policy` у своего PR — раздел «Отчёт ревьюеров»: вердикты дословно («соответствует», «замечаний нет», «критично: нет»).
2. **Сводка.** У машины сквозных тестов в журнале есть блок «Сквозные тесты, машина N/6» (`scripts/e2e-summary.mjs`): что упало, что прошло только со второй попытки, что не запускалось, какой запуск оборван. Журнал задания — через инструмент GitHub `get_job_logs` с сохранением в файл (прямые ссылки на журналы из облачной сессии закрыты), затем `node scripts/ci-log-summary.mjs <файл>` — только строки о падениях, без журналов контейнеров.
3. **Разбор.** Агент `ci-triage`: сводка, путь к файлу журнала, ветка и PR, итог последнего ночного прогона main и падения других открытых PR за сутки (у агента нет доступа к GitHub — передать ему). Он скажет вид (код, тест, main, инфраструктура, отмена), место и типовую ошибку.
4. **Исправить всё за один заход:** упавшие тесты, «прошло со второй попытки» (№ 10) и «не запускалось» (№ 18) — последние запустить локально по одному файлу, если они на экранах, которые задевает правка. Тест не пропускать и не отключать.
5. **Перезапуск без правки** — один раз и только при инфраструктуре (скачивание образа или пакета, лимиты GitHub, сеть, место на диске; № 20).
6. **Новая ошибка** (ci-triage: «новая») — строкой в `docs/typical-mistakes.md` в том же PR: что было, как правильно, кто ловит.
7. **Сообщить** одной строкой в своём треде: что упало и почему, что исправлено. Ночной прогон main красный — исправление первым делом, строка в тред «Общий план и статус задач».

## Оборвано по пределу времени
- Сводка «запуск оборван» и шаг тестов отменён по пределу — смотреть блок «Соединения базы (кто чего ждёт)»: транзакции `idle in transaction` и запросы, ждущие пул, — зависание кодом (№ 11); тесты шли до конца и было предупреждение «близко к пределу» — тестов стало больше предела (№ 22): разгрузить машину отдельным PR (правка `.github/` — её сливает заказчик).
