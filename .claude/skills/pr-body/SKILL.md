# Описание PR

`pr-policy` (`.github/workflows/pr-policy.yml`) читает раздел «## Отчёт ревьюеров» описания и без строк `spec-reviewer` и `security-reviewer` с вердиктом из инструкций агентов PR не сливает. За пакет 14.11 он был красным 9 раз (#258, #261, #262, #263): «**spec-reviewer** — соответствует» вместо «- spec-reviewer: соответствует», нет строки агента, слово «критичных» в пересказе (docs/typical-mistakes.md № 29, 35, 46). Каждый такой красный — PR стоит, пока тред не заметит и не поправит описание.

## Порядок
1. Разделы — по `.github/pull_request_template.md`: «Что сделано», «Задача и раздел ТЗ», «Как проверить на стенде», «Отчёт ревьюеров», «Вопросы к ТЗ». Коротко, по-русски, что и зачем.
2. **Отчёт ревьюеров.** Первая строка ответа каждого агента — готовая строка отчёта: скопировать её как есть, не пересказывать и не оформлять жирным:
   - `- spec-reviewer: соответствует; <главное>`
   - `- security-reviewer: замечаний нет; критично: нет; <главное>`
   - `- test-reviewer: замечаний нет; <главное>`
   - `- migration-reviewer: …` — если правка меняет `packages/db/migrations` или `packages/db/src/schema`.
   Строку агента руками не править и вердикт не менять. Агент нашёл критичное или «не соответствует» — исправить код и пройти агентом снова (п. 4), его новая первая строка заменяет старую. Подробности агентов и уже исправленное — отдельными пунктами под строками, без корня «критичн…»: `pr-policy` пропускает его только в «критично: нет» и «критичных нет».
3. **Проверить до PR** — той же функцией, что в CI:
   ```sh
   node -e "import('./scripts/check-pr-policy.mjs').then(m => { const p = m.checkPrPolicy(require('fs').readFileSync(process.argv[1], 'utf8')); console.log(p.length ? p.join('\n') : 'pr-policy: ок'); })" <файл описания>
   ```
   Хук `guard-pr-body` делает то же перед `create_pull_request` и `update_pull_request` инструментов GitHub и не пропускает описание с ошибкой. `gh pr create` / `gh pr edit --body` хук не видит — описание для них проверить этой командой.
4. Повторный проход агента после исправления — заменить его строку новой первой строкой, старую не оставлять.
5. Правка описания перезапускает только `pr-policy`, CI кода — нет: красный только `pr-policy` из-за формы — правится описание, не код; «нашёл то, что нельзя сливать» — правится код и агент проходит снова (скилл `ci-red`).
6. Конец описания — строки подписи из системного напоминания сессии, если они есть.
