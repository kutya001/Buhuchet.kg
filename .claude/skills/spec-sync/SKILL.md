# Обновление spec/

`spec/` — копия ТЗ, прототипа и данных из репозитория прототипа; руками не правится. Новая версия прототипа часто меняет тексты словаря, шаблоны сообщений бота и демо-данные — а сквозные тесты и тесты пакетов сверяют их строками. Так упали #234 и #245 (docs/typical-mistakes.md № 1).

## Порядок
1. Только один такой PR одновременно (CLAUDE.md): пока открыт чужой PR с `pnpm spec:sync`, свой не открывать; после его слияния обновить ветку.
2. Ветка от свежего main, `pnpm spec:sync` — без другой работы в PR.
3. **Что поменялось.** `git diff --stat -- spec/` и по существу:
   - тексты словаря и шаблоны сообщений — `git diff -- spec/data/refDB.json` (localization, messageTemplates), тексты лендинга;
   - демо-данные — `spec/data/demoDB.json`.
4. **Старые строки в тестах.** Для каждого удалённого или изменённого текста и шаблона — `git grep -nF '<старая строка>' -- e2e packages apps` и поправить найденное в этом же PR (тексты — из словаря, а не копией, скилл `e2e-test`).
5. **Тексты в двух местах.** Ключи словаря, которые есть и в `refDB.json`, и в `packages/domain/src/l10n/*-texts.ts`, должны совпадать (`packages/db/src/l10n.test.ts`); ключи шаблонов бота — с `refDB.messageTemplates`. Данные лендинга — `pnpm landing:data`.
6. **Наполнение опережает экраны** (новые поля демо-данных, которых ещё нет на экране) — пункт в `docs/deviations.md` (скилл `spec-deviation`), а не правка наполнения.
7. `pnpm check` (вместе с типами `e2e/` и загрузкой сквозных тестов), агенты-ревьюеры, PR. После слияния — одна строка в тред плана: другие потоки обновляют ветки.
