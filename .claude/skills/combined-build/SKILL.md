# Общая сборка

Заказчик просит сливать готовую работу нескольких потоков одним PR и одним полным прогоном CI. В #245 при такой сборке пропал помощник `pickContractor` одной ветки, старые тексты другой ветки сломали тесты третьей, и сборку собирали два треда (docs/typical-mistakes.md № 16, 23).

## Перед началом
1. Сборку ведёт один тред — он назван в треде «Архитектура и план разработки» строкой «Общую сборку ведёт …». Нет такой строки — написать её и только потом начинать; есть другая — не начинать. После перерыва (лимит сессии, «Продолжай») — сначала проверить, не взял ли сборку другой тред.
2. Список веток и порядок слияния — в описании PR: сначала ветки с миграциями, потом остальные.

## Сборка
3. Ветка от свежего main; каждую ветку — `git merge --no-ff origin/<ветка>` (не rebase), конфликты — оставить обе строки в общих списках (CLAUDE.md).
4. **После каждого слияния** — проверить, что ветка пришла целиком: `git diff origin/<ветка> HEAD -- <файлы ветки>` показывает только чужие добавления, ничего из её строк не пропало; новые экспорты её помощников на месте.
5. **Миграции** — номера меняются один раз, после слияния всех веток, по порядку (скилл `db-migration`, «Миграции по очереди»); ссылки на прежние номера в `docs/` и комментариях — поправить.
6. **Старые строки.** Ветка поменяла текст, шаблон или формат — `git grep -nF '<старая строка>'` по всей сборке: тесты другой ветки могли сверять старую.
7. **Пункты docs** — `docs/decisions.md`, `docs/deviations.md`, `docs/acceptance-map.md`: оба пункта при конфликте, номера потоков не менять.

## Проверка
8. `pnpm check` один раз — в нём и типы `e2e/`, и загрузка сквозных тестов: пропавший помощник видно здесь, а не через полчаса на машинах CI.
9. Агенты-ревьюеры смотрят **стыки** веток (общие файлы, общие списки, чужие тесты, которые задевает каждая ветка), а не каждую ветку заново: в задании им — список веток и что каждая меняет.
10. Красный CI — скилл `ci-red`: исправить всё, что нашёл прогон, вместе с «не запускалось» и «со второй попытки», одним пушем.
11. После слияния — одна строка в тред «Общий план и статус задач» и каждому потоку, чья ветка вошла: их PR закрыть, ветки обновить.
