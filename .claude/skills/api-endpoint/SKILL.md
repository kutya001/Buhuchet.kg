# Метод API

## Порядок
1. Схемы входа и выхода — в `packages/shared/src/<модуль>.ts` (их же использует форма интерфейса). Ошибки — `{ error: { code, message } }`, `code` — ключ словаря.
2. Маршрут — `packages/api/src/modules/<модуль>/<действие>.ts`: `createRoute` (метод, путь, `tags: ['<модуль>']`, `summary` по-русски, `request`, все ответы со схемами), обработчик типа `RouteHandler<typeof route>`.
3. Модуль регистрирует маршруты **цепочкой** в `createModuleApp().openapi(...).openapi(...)` и подключается в `src/app.ts` через `.route('/', <модуль>Module(deps))` — иначе метод не попадёт в типизированный клиент интерфейса.
4. Доступ: общий слой (`src/middleware/`) уже проверил вход и загрузил права сотрудника. У метода — нужное право из 39: `middleware: [requirePermission('<право>')] as const` в `createRoute` (нет права — 403 `forbidden`; метод для любого сотрудника — `requireEmployee`). Область «Свои / Все контрагенты» — `scopeOf(c.var.access!.subject, '<группа>')`; она фильтрует данные на сервере (условие в запросе), а не только в интерфейсе. Метод без входа — только явно в `PUBLIC_PATHS` (`middleware/session.ts`) и с причиной.
5. Данные организации — только внутри `withOrgContext(deps.db, orgContextOf(c), async (tx) => …)`: организация и автор — из сеанса, никогда из запроса. Никаких запросов без контекста к таблицам с `org_id`.
6. Изменение важных данных — в истории, в той же транзакции: правка записи с версией — `updateWithHistory(tx, { table, entity, id, version, patch, where })` из `@buhuchet/db` (устаревшая версия → `RecordChangedError` → 409 `record_changed` «Запись изменена другим пользователем», нет записи или она вне области → 404 `not_found`; отвечает общий обработчик ошибок), создание и прочие действия — `writeHistory`. `patch` собирать из явного списка полей, а не из тела запроса; область «Свои» — в `where`, а не проверкой после правки. Во входной схеме — `Uuid` для номера записи и `RecordVersion`; в ответах метода — `...versionedSaveResponses`. Ответ — только поля из схемы ответа (строку таблицы целиком не отдавать: в ней бывают хеши). История записи (`readHistory`) — только после того, как сама запись загружена с условием области.
7. Правила — вызовы `packages/domain`, не логика в обработчике. «Сейчас» — `deps.clock`, файлы — `deps.storage`, Telegram — `deps.telegram` (может быть null).
8. Тесты в `packages/api/src/modules/<модуль>/*.test.ts` (`app.request(...)`):
   - успех и проверка схемы ответа;
   - нет входа → 401, нет права → 403, область «Свои» не видит чужих контрагентов;
   - организация А не видит и не меняет данные организации Б (с `createTestDatabase`);
   - неверные данные → 400 `validation_failed`; устаревшая версия → 409 `record_changed`, правка не затирает чужую; изменение видно в истории с автором.
9. Покрытие пакета ≥ 80 % (`pnpm --filter @buhuchet/api test:coverage`). Метод виден в `/api/openapi.json`.
