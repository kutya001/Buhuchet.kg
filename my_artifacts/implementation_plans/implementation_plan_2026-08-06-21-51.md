# Implementation Plan - Разделение Заявок на «Входящие» и «Исходящие» с Логической Матрицей Статусов

**Дата создания:** 2026-08-06 21:51  
**Статус:** Ожидает утверждения пользователя  

---

## 1. 🎯 Цель Проекта
Разделение единого реестра партнерских заявок организаций на 2 независимые логические под-вкладки с соответствующими статусами и доступными действиями:
1. **📥 Входящие заявки (`incoming`):** Заявки от других организаций в адрес нашей компании (`target_company_id === currentCompanyId`).
2. **📤 Исходящие заявки (`outgoing`):** Заявки, отправленные нашей организацией другим компаниям (`requester_company_id === currentCompanyId`).

---

## 2. 🛠️ Архитектура Изменений и Логика Статусов

### 2.1 Под-вкладка «Входящие заявки» (`incoming`)
- **Фильтрация:** `p.target_company_id === currentCompanyId`.
- **Под-фильтры по статусам:**
  - *Все* (`all`)
  - 🔵 *Ожидают ответа* (`pending`)
  - 🟢 *Принятые* (`approved`)
  - 🔴 *Отклоненные* (`rejected`)
- **Действия пользователя:**
  - При `pending` ➔ Кнопка **`[ Принять в сеть ]`** (`approved` + автоматическое создание взаимных контрагентов в обеих компаниях) и Кнопка **`[ Отклонить ]`** (`rejected`).
  - При `approved` ➔ Кнопка **`[ Приостановить ]`** (`suspended`).

### 2.2 Под-вкладка «Исходящие заявки» (`outgoing`)
- **Фильтрация:** `p.requester_company_id === currentCompanyId`.
- **Под-фильтры по статусам:**
  - *Все* (`all`)
  - 🟡 *На рассмотрении у партнера* (`pending`)
  - 🟢 *Подтверждены партнером* (`approved`)
  - 🟠 *Отозваны вами* (`recalled`)
  - 🔴 *Отклонены партнером* (`rejected`)
- **Действия пользователя:**
  - При `pending` ➔ Кнопка **`[ Отозвать заявку ]`** (`recalled`).
  - При `recalled` / `rejected` ➔ Кнопка **`[ Повторить запрос ]`**.

---
