# Глубокий Анализ, Код-Ревью и План Оптимизации Производительности (Суперадминка & Вся Платформа)

В данном документе изложен детальный технический анализ причин медленной работы, перезагрузок интерфейса при действиях (модерация, смены статусов) и нагрузок на базу данных, а также комплексный план оптимизации по 3 основным направлениям: **Фронтенд & UX**, **Бэкенд & Server Actions**, **База Данных PostgreSQL**.

---

## 🔍 Глубокий Анализ и Причины Проблем (Code Review)

### 1. Проблемы Фронтенда и UX (Frontend Overhead)
- **Тотальная перезагрузка при одном действии:**
  При модерации одной организации (нажатие «Одобрить», «Запросить исправления», «Заблокировать») в `app/super-admin/page.tsx` вызов `await loadData()` заставляет фронтенд делать **6 ТЯЖЕЛЫХ ПАРАЛЛЕЛЬНЫХ ЗАПРОСОВ**:
  1. `getPendingCompaniesAction()`
  2. `getAllCompaniesAdminAction()`
  3. `getAllUsersAdminAction()`
  4. `getAllSystemFilesAction()`
  5. `getAllDocumentsAdminAction()`
  6. `supabase.from('file_categories').select('*')`
  
  Из-за вызова `setLoading(true)` весь интерфейс моргает, блокируется лоадером (`<Loader2 animate-spin />`) и перерисовывается.
- **Отсутствие Оптимистичного Обновления (Optimistic UI Update):**
  Вместо того чтобы моментально перевести статус компании в `'active'` в локальном состоянии (Optimistic Mutation), клиент блокирует экран и перезапрашивает полные массивы из базы.
- **Повсеместность проблемы в других модулях платформы:**
  В модулях `Documents` (принятие документа), `Counterparties` (ответ на партнерскую заявку), `Employees` (смена роли) и `Files` при совершении действий вызывается полный перезапрос списков `loadData()`, создавая неприятный эффект "перезагрузки страницы".

### 2. Проблемы Бэкенда (Backend Overhead)
- **Отсутствие Ленивой Загрузки вкладок (Lazy Loading):**
  При входе на `/super-admin` приложение сразу запрашивает всех пользователей всех компаний, все сканы R2 и все B2B документы в системе, даже если суперадмин смотрит только первичное окно заявок организаций.
- **Запросы `select('*')` без лимитов и пагинации:**
  `getAllUsersAdminAction`, `getAllSystemFilesAction`, `getAllDocumentsAdminAction` выбирают все строки из базы без `.range(from, to)` и фильтрации.
- **Избыточный `revalidatePath`:**
  В Server Actions вызов `revalidatePath` приводит к инвалидации всего серверного кэша страницы.

### 3. Проблемы Базы Данных (Database Overhead)
- Отсутствуют целевые составные индексы для фильтров модерации и статусов: `companies(status, created_at)`, `documents(sender_company_id, receiver_company_id, status)`.

## 🛠️ Детальный План Решений и Оптимизации

### Step 1: Оптимизация Базы Данных (SQL Indexes)
**Файл миграции:** `supabase/migrations/20260731080500_performance_optimization_indexes.sql`

Добавить составные индексы для мгновенного выполнения запросов:
```sql
CREATE INDEX IF NOT EXISTS idx_companies_status_created ON public.companies(status, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_documents_status_sender_receiver ON public.documents(sender_company_id, receiver_company_id, status);
CREATE INDEX IF NOT EXISTS idx_users_company_active ON public.users(company_id, is_active);
```

### Step 2: Бэкенд — Ленивые и Пагинированные Server Actions
**Файл:** `app/super-admin/actions.ts`

- Разбить тяжелый `getAllCompaniesAdminAction` на независимые пагинированные функции с поиском.
- Создать независимые экшены под каждую вкладку, чтобы не загружать неиспользуемые сущности.

### Step 3: Фронтенд — Внедрение Оптимистичных Обновлений (Optimistic UI Updates)
**Файлы:** `app/super-admin/page.tsx`, `app/dashboard/documents/[id]/page.tsx`, `app/dashboard/counterparties/page.tsx`, `app/dashboard/employees/page.tsx`

1. **Суперадминка (`/super-admin`):**
   - При клике «Одобрить компанию»:
     - Моментально обновляем статус компании в локальном массиве `allCompanies` на `'active'` и удаляем из `pendingCompanies`.
     - **НЕ ставим `setLoading(true)` и НЕ вызываем `loadData()`!**
     - В фоне вызываем `approveCompanyAction(id)`. Если сервер вернул ошибку — откатываем локальное состояние.
2. **Модуль Документов (`/dashboard/documents/[id]`):**
   - При клике «Принять» / «Обработать» / «Отозвать» моментально обновляем локальное состояние `document.status` в UI без вызова лоадера и перезагрузки.
3. **Модуль Контрагентов (`/dashboard/counterparties`):**
   - При ответе на заявку на партнерство (Принять/Отклонить/Прекратить) моментально обновляем статус в локальном массиве `partnerships` без блокировки экрана.

### Step 4: Ленивая Загрузка Вкладок (Tab-Based Lazy Loading)
- Данные для вкладок «Пользователи», «Файлы», «Документы», «Инспектор БД» подгружаются **только при клике на соответствующую вкладку**, а не заранее при входе на страницу.

## 📊 План Верификации

### Автоматические тесты & Сборка
- Запуск проверки типов TypeScript: `npx tsc --noEmit`.
- Проверка полноценного билда Next.js: `npm run build`.

### Ручные сценарии проверки (UX / Performance QA):
1. **Тест мгновенной модерации в Панели Суперадмина:**
   - Нажать кнопку «Одобрить» у заявки организации.
   - **Ожидаемый результат:** Статус компании мгновенно меняется на «Верифицирован», таблица не моргает, интерфейс НЕ блокируется лоадером, полная перезагрузка отсутствует.
2. **Тест скорости переключения вкладок:**
   - При первичном входе на `/super-admin` загружаются только компании (скорость входа увеличивается в 4-5 раз).
3. **Тест мгновенного принятия документа:**
   - В модуле Документы нажать «Принять».
   - **Ожидаемый результат:** Бейдж статуса моментально становится зеленым («Принят») без ререндер-вспышек.
