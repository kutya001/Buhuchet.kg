## 🚀 ПЛАН ОПТИМИЗАЦИИ И ДАЛЬНЕЙШЕГО РАЗВИТИЯ (REVIEW ACTION PLAN)

Этот план определяет 3 логических шага по поддержанию идеальной архитектуры и производительности приложения:

### Шаг 1: Замена остаточных типов `any` на строгие Zod-интерфейсы
- **Цель:** Исключить возможность неявной типизации `any` в Server Actions.
- **Файлы:**
  - `app/dashboard/documents/actions.ts`: заменить `data: any` в `createB2BDocumentAction` на `z.infer<typeof createDocumentSchema>`.
  - `app/(auth)/onboarding/actions.ts`: заменить `data: any` в `createCompanyOnboardingAction` на `CompanyOnboardingInput`.

### Шаг 2: Автоматическая очистка физических сканов в Cloudflare R2
- **Цель:** При полном редактировании/удалении черновиков B2B документов удалять старые сканы не только из таблицы `document_files`, но и выполнять физическое удаление объекта из Cloudflare R2 по ключу `file_path_r2`.
- **Файлы:**
  - `lib/r2.ts`: добавить экспорт `deleteR2Object(fileKey: string)`.
  - `app/dashboard/files/archive-actions.ts`: добавить вызов `deleteR2Object` при удалении скана.

### Шаг 3: Автоматический кэш-контроль для Telegram Webhook
- **Цель:** Гарантировать обработку Telegram вебхуков быстрее 2 секунд (требование Telegram API) через фоновые очереди.
